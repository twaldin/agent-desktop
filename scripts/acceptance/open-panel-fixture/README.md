# Open panel acceptance

Run `bun scripts/acceptance/open-panel-fixture/run.ts .data/open-panel-run` from the repository. Add `--git` for the Review/order/singleton cases. Each output directory must be new. Add `--terminal-bundle /absolute/verified/darwin-arm64` for the positive Terminal lane; the actual host validates the bundle and must advertise its native capability.

The fixture mounts the production App in Electron, creates a disposable authenticated host and session, and uses the production WindowStateStore. Electron pointer and keyboard input exercises the empty launcher, shared menu glyphs, Files, Browser new-tab draft, Side chat draft, menu dismissal/focus, hide/reopen, Review in both regions, document reload, and the projectless unavailable state. Source fingerprints before/after, screenshots, geometry, IPC calls, failures, and cleanup outcomes remain in the requested output directory.

The IPC adapter is fixture-owned. Host reads and commands reach the real service; optional APIs remain absent unless explicitly configured. Without a bundle Terminal is unavailable. With a verified bundle, production terminal transport helpers and real host endpoints create an isolated tmux PTY; Electron character/key input executes a harmless printf/pwd command, native history displays its output, hide/reopen retains the terminal descriptor, and the explicit Stop shell action terminates it before viewer removal. Native terminal events use their separate production-shaped channel. Browser URL submission and provider requests are not exercised; the native worker rejects provider fetches and the host permits only loopback fetch. This does not prove Electron production IPC, native browser behavior, the complete Terminal regression suite, external OAuth, MCP app/artifact producers, physical multi-host operation, or pixel parity. The candidate dependency installation must be qualified separately.

The host/profile/project are isolated and removed only after a clean host shutdown. Failed startup/cleanup directories are retained. Existing user instances and configuration are untouched.
