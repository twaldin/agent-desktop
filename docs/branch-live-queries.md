# Host-owned branch query execution

`BranchLiveQueries` is the host-private execution owner for recent, default and base branch subscriptions. HostWorkspaces now consumes it through its internal `subscribeBranchQuery` API. The host event socket exposes a separate branch subscription protocol. Desktop `BranchQueryConnection` owns logical observers across connections; main/window/preload source now routes those observers, and BranchInventory now consumes those observers for recent/default/base inventory. Typed search and other workspace methods retain their separate query APIs. `docs/repository-watch.md` describes the separate metadata watch and renderer invalidation adapters.

The registry gives each subscriber its own generation, result callback, cancellation and recovery state. Initial reads run immediately. Relevant repository changes invalidate matching host/common-directory/root subscriptions; later local refreshes coalesce for100ms, while remote refreshes are immediate. A change during an in-flight read suppresses that generation's result and queues a fresh read after the current one finishes. Refresh promises settle on the final generation or subscriber removal. Ordinary branch errors publish a failure; they do not trigger the status/review methods' separate automatic error-retry policy.

Equivalent active reads share by host/common-directory/root/normalized query, including query parameters. Different reads serialize by host/common-directory even across linked roots; other hosts or common directories remain independent. Canceling one observer does not cancel work still used by another. The last consumer aborts the shared request, but a runner ignoring cancellation still holds its repository queue until it settles. New same-ID registrations cannot receive a retired registration's result or be removed by its old disposer. IDs are registry-local; future transport must separately enforce connection identity and request limits.

Each completed result carries current degraded-coverage state. Recovery transitions invalidate matching host/root subscriptions. Explicit recovery selects only requested, degraded subscriptions and asks the owning integration to prepare recovery once per root. It does not silently mark coverage healthy. Results are copied per callback so a local observer cannot corrupt another observer's result.

## Admitted HostWorkspaces consumer

The internal API snapshots its original catalog stamp and target before acquisition. It normalizes the supported query, retains the actual watch lease and obtains the actual shared watch entry's captured root/common-directory metadata, rather than the joining subscriber's newly discovered tuple. After acquisition it constructs a reader from the original selected directory and verifies the root/metadata tuple again before registering. The retained reader checks directory identity for later Git reads; this detects observed replacement, not an atomic filesystem lease. Standalone files, missing/foreign owners and unsupported queries cannot acquire this path.

A settled watch error becomes `requiresRecovery`, not healthy readiness. The registry now exposes its per-entry change/recovery callbacks once per canonical watch, alongside the existing per-target workspace events. This avoids duplicate live invalidations when project and session subscriptions share that watch. Catalog publication latches owner loss even across return to the original bytes. Query unregister precedes watch abort/release; pending acquisition is tracked so late resources are drained. The existing server watch-shutdown and catalog-reconciliation calls now include these query owners, but those server call sites have not been run in this acceptance.

Post-watch root and metadata discovery receive the admission AbortSignal, including every Git command and checks around filesystem identity reads. Actual branch methods receive the shared query AbortSignal through root preflight and consumption. Recent scans coordinate cancellation through their cache; sent Default/Base dependencies have a separate cache-owned signal as described below. Recovery invalidates both cache families before refreshing queries and existing workspace observers. An aborted sent command or retired subscriber cannot publish a result into a replacement owner. Host shutdown waits for admitted reads and watch cleanup before its caller may close the store.

## Authenticated host result transport

HostState advertises `branchQueries.version = 1`. The existing authenticated `/v1/events` socket accepts distinct `branch-query` retain, inspect, release and recover frames. Each contains exact host, socket-local subscription ID, catalog target and normalized query. Incoming frames remain limited to 1024 bytes. Standalone paths, unsupported methods, owner/query changes under an existing ID and malformed frames close the peer. Local refresh scheduling is derived from the server connection, not a client flag.

Each peer permits at most 128 active/pending/releasing branch queries and 2048 lifetime IDs. Released and failed IDs are tombstones; a new ID or new connection is required for fresh admission. Inspect never acquires, and recover only refreshes an already admitted degraded subscription, coalescing overlapping requests. These limits are app transport adaptations, not measured reference values.

Status and typed result messages are connection-local and never advance the durable HostEvent cursor. Results retain generation and degraded-coverage state; initial results wait for admission readiness, stale generations are discarded, and private host IDs are replaced with the exact wire identity. Recent/default/base result shapes are validated before delivery. Error text is bounded to 1000 characters, outgoing frames to 512 KiB and the existing socket buffer to 8 MiB; overflow or send failure closes and drains the peer. Branch names are bounded to 4096 characters and recent results to the requested maximum of 100; malformed or oversized owned results are not silently truncated into valid results.

Host lease cancellation and closure notify the peer when catalog ownership ends. Revocation, disconnect and release abort pending admission before awaiting cleanup; a late lease is disposed without publishing readiness. Shutdown includes both watch and branch peer drains alongside HostWorkspaces shutdown. A released status with an error does not claim clean acquisition or resource disposal. These socket authorization, dispatch and shutdown call sites are source/typecheck evidence only under the launch hold.

## Desktop connection owner

`BranchQueryConnection` keeps exact catalog-target/query observers across socket replacement, while each connection gets fresh wire IDs and result generations. It sends no request until that connection's first replay-complete HostState advertises `branchQueries.version = 1`. Unsupported hosts remain visibly unsupported without a one-shot fallback. After initial admission, an ordinary same-host state contradicting that capability immediately retires readiness and requires reconnect; it need not carry another replay-complete marker. The separate public repository-watch observer capability is not a prerequisite for the branch protocol's internally owned watch admission.

Matching pending and ready statuses are distinct from typed query results. Results before ready, malformed payloads and changed host/target/query bindings close this logical connection. Results advance only on a newer generation. Query failure remains a ready subscription with a failed update and explicit recovery; lifecycle failure cannot be revived by late ready/results. Reconnect discards the old update and generation. Unknown valid IDs and callbacks from replaced connections cannot create or revive observers.

Logical release sends one release for an allocated wire, never reacquires, and cannot affect another observer. Delivery snapshots nested results and request inputs. Callbacks may release or replace connections synchronously; a pending callback that releases before retain dispatch prevents acquisition. The controller bounds logical observers to128 and wire history to2048, and rejects repeated wire IDs. Controller disposal releases its wires but does not close the shared event socket.

## Window and event-stream integration

`BranchQueryWindows` binds each renderer subscription ID to its original host/target/query and original document token. Endpoint lookup receives a current-owner guard; release, navigation, renderer loss or shutdown retires the pending owner before a late lookup can retain. Each completed document load grants a new token; an old, absent or foreign token cannot dispatch. Preload caches its token only for that isolated document. Unknown inspect/recover is read-only unavailable, release creates a tombstone, and a repeated ID cannot redirect or restart admission. Windows independently own their observers and copied nested results. Per-window limits include pending lookups and retired history.

The main event stream attaches both watch and branch connections through `attachWorkspaceQueryEvents`. Connection-local frames are consumed before the durable cursor. Valid state reaches both capability gates; a fatal frame or capability contradiction retires both clients and closes the current socket. Failure marks the shared sender unavailable before notifications, and both clients notify the shared closer before their own disconnect listeners. This prevents a listener from issuing a branch request during another client's fatal watch response. A replaced socket cannot close or overwrite a newer attachment. Navigation/close/gone and application termination release both window owners; application termination also disposes both stream clients.

Main and preload expose optional `branchQuery`/`subscribeBranchQuery` alongside the existing one-shot query and repository-watch APIs. The original trusted-main-frame check and completed-document token barrier are shared by the two IPC paths. Main/preload call sites are typechecked and source-inspected only; controlled owner/router tests do not establish Electron navigation, actual IPC, authentication or socket behavior.

## Renderer observer prerequisite

`BranchQueryObserver` now supplies one explicit renderer subscription lifetime. Constructing it performs no bridge operation. Its caller starts it only for a committed owner and must dispose it on owner loss/unmount; BranchInventory consumes it from committed hook activation through its exact WorkspaceState owner. It snapshots exact host/target/query/ID, subscribes to main delivery before sending retain, and treats invocation completion separately from readiness. Disposing before queued retain sends nothing. Once sent, disposal unsubscribes and sends one release even if admission is still pending. Fulfilled release means main has retired that logical ID, not that every native resource has drained.

Main-to-renderer payloads have a strict shared parser for copied owner/query, phases and typed nested updates. Foreign host/ID deliveries are ignored; malformed or changed bindings under the same logical ID are terminal. Query errors remain ready updates, allowing explicit coalesced recovery; lifetime errors require a new explicit observer. Disconnect/reconnect state is carried from the main client, whose connection-local generation checks remain authoritative. No automatic one-shot fallback or automatic fresh-ID retry is introduced.

Disposal invalidates delivery and clears the local snapshot before cleanup. Subscription cleanup cannot prevent release dispatch, and combined errors remain observable through the disposal promise. The inventory owner awaits and handles that promise before replacing a failed lifetime. Tests cover controlled renderer/window/client composition, not mounted React, actual preload/IPC, socket or native behavior.

## Required public integration

The recent-scan and Default/Base dependency caches are separate implementations described below; neither substitutes for the required physical integration. The inventory consumer uses the advertised protocol, retains subscriptions for the exact owner lifetime and fails visibly on unsupported hosts. The main/preload and host socket implementations still require actual authenticated socket and physical lifecycle acceptance. The execution class alone does not supply transport readiness, owner discovery or physical reconnect. Host peer bounds and typed result validation now exist in the separate transport adapter; complete native query-parser compatibility remains required. Search remains a distinct renderer query path; no all-method live-query engine is claimed.

## Committed inventory consumer

WorkspaceState creates inert branch observers with its own host and catalog target; standalone files have no such owner. BranchInventory starts independent recent/default subscriptions (recent/base for starting state) only after committed activation. Renderer status/HEAD/draft notifications no longer dispatch duplicate inventory reads: the admitted host query owns metadata invalidation and scheduling. Typed search still uses its existing query and invalidation path. The existing repository-watch retention remains for status and selection consumers.

Close, owner replacement or an observed connection loss invalidates both local generations before outward notification, clears inventory and retires observers. Each method waits for its predecessor's release acknowledgement before admitting a new ID; a rejected release remains fenced across retry and reopen. This is a logical main-owner acknowledgement, not native cleanup confirmation. A later method can settle independently while its sibling release or result remains pending. Repeated connected notifications do not restart healthy observers.

Ready query errors remain visible. Explicit retry uses same-ID recovery only when watch coverage is degraded, because the host's recovery method excludes healthy subscriptions. Other retries replace the subscription after acknowledged release. Successful degraded results remain visible with a separate warning and retry control in the existing menu status area. No old-host or absent-bridge one-shot fallback is supplied. Saved starting selections, remote identity, mutation owners and selection admission are unchanged.

Consumer evidence uses actual BranchInventory, WorkspaceState and BranchQueryObserver with controlled delivery and React phase drivers. Existing menu fixtures use explicitly controlled observer doubles; acceptance drivers expose deterministic branch status messages and are compiled only under the launch hold. These are not mounted React, actual main/preload IPC, socket, native watcher, popup/pixel or whole-app acceptance.

Synchronous status delivery during observer registration can retire the observer before subscribe returns its cleanup. The returned cleanup is handed to the already-installed disposal microtask, which reads and clears it once. A throwing cleanup rejects the original retained disposal promise and every later disposal; no retain is queued after retirement. A void cleanup's incidental Promise return remains ignored, including reentrant disposal, so it cannot self-await. This is controlled callback scheduling evidence, not actual IPC/native timing.

## Recent-branch read cache

`RecentBranchCache` belongs to one HostWorkspaces instance. WorkspaceService still verifies the original directory and resolves stable root/common/git/head/index paths before every cached recent read. The private cache identity also includes the observed metadata directory device/inode values; it does not grant file authority or promise an atomic filesystem lease. Values are full top-100 local-tip scans, with requested limits applied afterward, and each consumer receives a copy.

One-shot recent reads and the one-shot default local-name fallback use a separate 250 ms stale/GC entry. Live recent/default fallback reads use an indefinitely fresh entry only when the actual shared watch has finished setup, remains owned, matches those metadata paths and reports healthy coverage. Different limits can therefore reuse the same completed scan; they still have separate subscription generations in the query owner. Base discovery executes first for Default and never consumes this recent cache. Its F4 dependency cache has separate lifetime rules below.

Config, HEAD, local-ref and remote-ref invalidations retire live recent entries before query refresh. Other metadata changes invalidate short-lived entries according to the pinned short-lived policy; worktree-topology leaves recent entries alone. Watch-health transitions retire live entries. Explicit recovery and final watch retirement clear both modes, including pending entries' ability to populate a successor generation. Watch retirement installs its retained drain before synchronously invalidating reads, then drains watcher cleanup even if notification throws. Ordinary Git/worktree mutation exits invalidate the owning root even on uncertain errors; compound submissions carry their original resolved Git root into their publication callback. Prepared worktree creation also invalidates its source root.

Pending scans share an abort controller. One consumer leaving cannot abort another; final cancellation removes that entry and aborts the sent scan. An uncooperative scan is still awaited, and an invalidated completion cannot seed the replacement cache. Host shutdown stops cache admission and awaits pending reads alongside query/watch drains. Unlike native N6's private failed-command-to-empty mapping, operational Git failures remain visible under the existing OMP-backed error contract and are not cached as successful empty lists.

Controlled tests exercise the actual HostWorkspaces/WorkspaceService consumers with disposable Git and SQLite, plus explicit watcher callbacks, coverage loss and recovery. Cache clock tests establish the 250 ms boundary separately. They do not establish native watcher delivery, socket/IPC/React behavior, installed execution, performance improvement, or full Git-read-cache parity. The metadata preflight currently remains uncached and may cost more than the saved scan for small repositories; it is retained for ownership verification, not presented as a benchmark win.

## Default/Base dependency cache

`DefaultBranchCache` is a separate per-HostWorkspaces owner. The actual live and one-shot Default/Base methods use it after the same catalog and observed repository-identity preflight. It caches ordered remotes, local symbolic remote HEAD, remote-show default and individual remote main/master existence independently. Keys include method, exact remote/name, canonical root and observed metadata identity within that host. Default still performs base traversal first, then its separate top-ten recent fallback; no completed Default/Base result is cached.

Completed dependencies are indefinitely fresh, including confirmed null/false/empty results. Config events invalidate all four classes. Remote-ref events invalidate the three remote-specific classes, preserving ordered remotes. HEAD, local-ref, index and working-tree events leave these entries alone. Generic mutation completion likewise leaves them reusable, matching the pinned F4 dependencies rather than the recent cache. The current host has no set-config workspace action; any future equivalent of the pinned direct config writer must publish config invalidation. Explicit recovery and last-watch retirement invalidate all completed dependencies. A degraded watch alone does not switch this family to the recent cache's short-lived mode.

Pending same-key dependencies share one sent read. Like the pinned query client, matching or full invalidation retains an in-flight dependency, which can complete afterward and become fresh for that same observed repository identity. There is no N6 generation purge in F4. Observed repository replacement instead creates a separate owner map, so old completion cannot populate the replacement. Caller cancellation suppresses consumption and further traversal without aborting a dependency still owned by the cache. Shutdown stops admission, aborts cache-owned signals and awaits sent work; an uncooperative command is not claimed stopped early. Query subscription generations and original catalog guards continue to control publication independently.

Normal Git absence and allowed unsuccessful advertisement exits remain cached sentinels. Existing operational errors, output bounds and timeouts remain visible and uncached, preserving the app's established error contract rather than copying the pinned broad failure-to-sentinel behavior. The existing no-prompt locale/timeout settings for remote show are unchanged. No global configuration is modified.

Author-team preparation verifies fifteen exact pinned source windows and executes the extracted query core/invalidators with controlled promises. That comparison establishes same-key pending retention and completed tag invalidation, not a native worker, Git or full F4 comparison. Maintained tests cover dependency keys, negative entries, pending invalidation, identity changes, copying, cancellation and drain; temporary Git plus controlled watch callbacks exercise real service and HostWorkspaces consumption. No native watcher, socket, IPC, renderer, installed behavior, performance improvement or full Git-read-cache parity is claimed.
