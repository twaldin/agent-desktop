# Pull request discussions

Pull request details retain GitHub review-thread IDs, path, diff side/range, original positions, resolved state and the viewer's reported permissions. Pagination still finishes each thread's comments before advancing. Contradictory thread position, resolution or permission metadata between pages requires a refresh; it cannot silently preserve earlier authority. Matching an author name does not grant edit, delete or resolve permission.

Select a rendered changed-file line or range to add an inline comment. The saved draft binds the original host, GitHub account, pull request, inspected head and path/side/range. Before its REST POST the host checks the displayed head and a complete returned diff hunk. Missing, binary, truncated or out-of-hunk selections cannot be guessed from a blob. The REST request carries the original commit; a head preflight is not an atomic GitHub lock.

Replies, comment/review edits, comment deletion and resolve/unresolve use the original GraphQL node. The host rechecks the current authenticated viewer, node type, parent pull request and operation-specific permission before mutation. These node operations and ordinary issue comments do not acquire an unrelated head-equality requirement. Review decisions and new inline comments retain their head guards. The additive `reviewThreads: 1` capability enables discussion writes without enabling them against an older host.

All writes reuse the existing host journal and window-owned drafts. The exact original request is saved before dispatch; the returned receipt is saved before local success or text clearing. Once admitted, the host owns settlement even if the requesting window disconnects. Unknown responses remain unknown across restart, status checks and reopening. A new attempt requires a deliberate acknowledgement; it never replays an old request automatically. Missing original comments retain saved status recovery rather than rebinding to another visible comment.

Delete comment has an explicit permanent-deletion confirmation. Cancel and duplicate submissions are disabled while its request is pending. Reply/edit text survives Cancel, Escape, offline periods and document reload. IME composition does not submit; the existing Ctrl/Cmd+Enter handler remains available outside composition. Source selection and display changes retire pending local admission, while already-dispatched results stay with their original saved request.

The disposable acceptance flow runs `bun scripts/acceptance/pull-requests-app/run.ts <new-output-directory> --discussions`. It mounts the actual App and Pierre diff renderer, uses actual Electron document reloads and window persistence, and routes through the authenticated host, SQLite journal and a real child process implementing controlled `gh` responses. It never posts to GitHub. Connection events and GitHub permissions/results are controlled boundaries; this is not a proof of GitHub production permissions, physical cross-machine behavior, or complete reference pixel parity. Merge, checkout, Fix and chat association remain separate required flows.
