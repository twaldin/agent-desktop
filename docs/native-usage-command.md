# Native `/usage` in the desktop

The composer preserves the OMP 18.1.10 command parser and live command ownership. Bare `/usage`, `/usage show`, and invalid usage syntax use the existing session command route and native output handler. Report generation calls the original session's `fetchUsageReports`, including its native automatic reset policy. This differs from the conversation-menu Provider usage panel, whose report refresh only inspects AuthStorage reports.

Only the builtin `/usage reset [account|active]` enters the desktop confirmation flow. The host independently refuses builtin reset through generic command dispatch, after resolving extension/custom ownership. A command named `usage` supplied by an extension or custom command keeps its native dispatch precedence, including the literal token rules before builtin whitespace/colon parsing.

A reset invocation refreshes credits on the original host/session. The native helper determines account order and matching labels; opaque row references bind selection to the exact inspected row. No argument opens the chooser without preparing or consuming. A full account selector or `active` prepares an exact existing credit and presents separate Confirm and Cancel actions. It never supplies a confirmation answer automatically. Missing accounts, unmatched selectors and zero-credit selections display native semantic notices without preparing; these consume the invocation. Host/version, transport, original-owner and preparation failures retain the draft. Only the unchanged submitted draft can be cleared; concurrent edits remain.

The command chooser preserves active-first, credit-count and label order from the native helper. It does not infer an account from truncated display text, expose native credential IDs, fall back to another matching account after failure, or replace an unknown request. Existing prepared, dispatching or unknown requests must be resolved or inspected before another invocation. Refresh and matching are not credit redemption: the owning host revalidates original account evidence and credit identity before durable preparation and confirmation.

This source batch adds no new transport, generic RPC, worker entry or SDK patch. It depends on the original host's usage protocol version 1 and reset command version 20. Native policy, child lifecycle, worker recovery, shared automatic/manual account admission and physical provider acceptance retain their own verification gates. Controlled tests and a disposable App fixture do not establish real-provider or full parity acceptance.
