# Suggested saved outputs

The blank right panel of a non-Git conversation shows outputs from its original saved OMP branch. It uses successful native `write` resolved paths, retained `generate_image` bytes, retained MCP UI tool results, and explicit document links in a completed assistant response. Read inputs, failed tools, Markdown examples, scratch paths and arbitrary file mentions do not create rows. A completed response with exactly one explicit HTTP(S) URL containing a port can offer that website when no file/app output takes precedence.

Turns appear newest first. Within a turn, retained app results precede generated images (newest image first) and files. Canonical paths/resources deduplicate, and a generated image replaces a same-path file row. The reader examines the last 5,000 saved entries and selects at most 100 outputs; only those selected images are decoded. These limits are visible. It checks selected file paths on the original host without enumerating directories. Missing paths disappear; an inspection error retains prior rows but a click must complete a fresh successful inspection before proceeding. File metadata revisions detect observed changes; this is not an atomic filesystem lease.

Every read and opening captures the host, task, native entry, worker-owned output epoch and revision. Lost connection, task, bridge, branch source or UI lifetime invalidates retained admission. A queued file or browser insertion checks the original guard again. The website action persists the original ordinary browser creation request and uses its existing creation ticket/receipt flow. Closing the panel does not rerun tools or silently create an owner.

Generated images use a separate `source=generated` entry/index namespace. The host must explicitly acknowledge that namespace; an older host cannot accidentally answer with an input-image block. Existing image transfer, hash, concurrency and cache limits still apply. Files use the existing original-host viewer; declared MIME viewers and MCP results use their existing exact owner/resource channels. There is no generated-file path download API or tool replay.

The Suggested heading remains sticky under the action catalogue, with a measured scroll shadow, native button keyboard behavior, thumbnails and row dividers. This feature does not change the root-owned action catalogue order or strip.

## Remaining reference work

The pinned R4n fallback for a single edited HTML file is not implemented here. It requires a separate original-session, host/path/revision-bound read-only preview owner and actual HTML rendering; opening HTML source does not satisfy it. Native edit/AST-edit outcome projection will be assessed with that flow rather than treating requested edit paths as successful outputs. Google Drive/app-generation producers are not invented when no corresponding saved native result exists.

The controlled/native fixtures use an isolated deterministic model, actual OMP file/image tools, a local MCP server, and a declared local website in an isolated Chrome target. They establish those exercised backends and App interactions, not all browser backends, whole-package SDK validity, physical parity or a pixel comparison against an uncaptured reference screen.
