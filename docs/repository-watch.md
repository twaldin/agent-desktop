# Repository metadata watches

The host currently publishes workspace events for app-owned operations. The renderer consumes those events to invalidate branch inventory/search even when the HEAD/index revision is unchanged. External Git changes still require an actual retained watcher; this document does not mark that bridge complete.

`WorkspaceService.repositoryWatchContext()` is the host-private discovery prerequisite. It uses Git's absolute git-dir, common-dir, HEAD and index paths. Linked worktrees share refs/config but retain their own HEAD/index/config.worktree. Nested project directories resolve to the repository root without changing ordinary file access. Unborn repositories may have no index or current ref. Detached HEAD is explicit. The read checks canonical paths and directory identities before/after discovery and retains operational errors. These checks detect observed replacement; they are not an atomic filesystem snapshot or a future subscription lease.

`repositoryMetadataChanges` classifies absolute metadata paths. Current local refs invalidate HEAD; other local refs invalidate the local catalogue. An unknown HEAD classifies every local ref as a HEAD dependency until the watcher rereads it. Ref lock files are excluded. Shared FETCH_HEAD, packed-refs and remote refs invalidate remote catalogue reads. Config and worktree topology have distinct classes; unrelated objects, logs and other worktree indexes are excluded. Replacement of refs/info directories conservatively invalidates their children. This helper does not classify working-tree changes, synced-branch state, external ignore sources, or additional local branch dependencies used by review queries.

The reference is the pinned build7982 worker, `$ge` metadata targets/classification, `N8` ref lock filter, `P8`/`Qge` topology filter and `zge` path discovery. Primary evidence lives privately under `.data/repository-watch-2026-09-10/`; preparation prose is not runtime proof.

Remaining integration must retain watches only for subscribed owners, bind host/catalog/root/common-dir identity, handle missing/replaced directories and watch failures, and release resources after the final subscriber. Reference events coalesce per change type for1000ms; active live queries serialize/recheck generations, with local100ms refresh and remote immediate refresh. The frontend retains eligible ever-open query observers after popup closure, then releases unobserved subscriptions after250ms. Ref-only changes must reach the existing renderer invalidation path without repurposing the HEAD/index mutation revision. Actual filesystem delivery, transport/reconnect, linked-worktree fanout, ignored paths, recovery and physical acceptance remain required. No host service or native watch is started by metadata discovery.

Focused validation: `bun scripts/test.ts apps/host/src/workspace/repository-watch.test.ts` uses disposable Git repositories plus controlled discovery failures and pure path classification. It does not exercise fs.watch, a server, IPC, React, or installed artifacts.

## Metadata resource owner

`RepositoryMetadataWatcher` now implements the directory-watch resource owner. It discovers the shared and worktree-specific targets from the context above, watches ref directories recursively, and watches the worktrees parent before listing its children. Optional missing metadata stays covered by parent watches; startup failure and unexpected watch closure expose recovery state. Replacing a directory retires its previous callback generation. Coverage recovery invalidates all metadata kinds. Per-kind change delivery coalesces for 1000 ms, preserves events arriving during an outstanding delivery, and drains accepted delivery and late watch acquisition when disposed.

The owner predicate is mandatory and observed loss permanently retires this instance. A different canonical context cannot silently replace the admitted one. The caller still must provide the actual catalog/host identity predicate and subscribe/unsubscribe it; this class has no registry, endpoint or renderer consumer yet. A metadata context read is not an atomic ref snapshot, and this class cannot detect ownership loss that its caller never reports. HEAD events retire the remembered ref while metadata is refreshed. Change delivery carries repository paths, not an invented current branch when HEAD is unknown. Healthy targets continue delivering alongside visible partial-coverage errors. Each failed target owns its 1-second-to-60-second exponential retry timer. Rescans and other targets cannot spend or reset that backoff; a session that stays active for at least 30 seconds resets its next closure retry to 1 second. Removing a target or disposing the owner cancels its timer. Context discovery, child listing and delivery failures retain a separate owner recovery timer. Recovering a target invalidates its metadata kinds even while another target remains unavailable. The initial query must run after watch acquisition; events from before acquisition are not a historical event log.

The production adapter uses [Bun's documented node:fs watch API](https://bun.sh/guides/read-file/watch), closes owned sessions and removes timers. This documentation is API evidence, not proof of the pinned runtime's OS coverage. Controlled lifecycle tests inject directory metadata, watch sessions and a clock; they do not start the native adapter. Recursive coverage, filesystem errors and event naming still need macOS/Linux runtime acceptance. Working-tree/synced-branch/ignore/review-dependency/reftable support remains required in separate work. Host startup alone does not retain a metadata watch; an explicit authenticated subscription is required.

Focused resource tests: `bun scripts/test.ts apps/host/src/workspace/repository-metadata-watcher.test.ts`.

## Retained catalog subscriptions

`HostWorkspaces.retainRepositoryWatch(target, signal)` now binds a project or session to its current host catalog stamp before metadata discovery. It returns a lease after the initial watch attempt settles; `lease.error` separately reports degraded coverage. The initial live query must follow that ordering boundary and must not infer healthy coverage merely because retain resolved. Standalone file paths do not grant repository subscriptions. The caller's abort signal and idempotent lease disposal both release ownership.

The host-local `RepositoryWatchSubscriptions` registry shares one resource per canonical repository root, matching the pinned host-plus-root key. The first entry inserted after metadata discovery captures its paths until final release; later same-root subscribers do not replace them. Nested catalog owners share that entry, while linked worktrees with distinct roots retain separate resources even when their common directory matches. Each event fans out only to still-current retained targets, deduplicating duplicate subscriptions to one target. Catalog publication rechecks retained stamps; an observed loss permanently retires that lease. The remaining live-query subscription transport must abort/release on client observer lifetime and reconnect, not infer retention from event replay.

The final release drains the watcher disposal attempt before a new subscription to the same repository may acquire a replacement. Matching the pinned recovery lifecycle, a failed disposal does not permanently poison the registry entry. The release and eventual shutdown still report the error, and callbacks from the retired resource cannot deliver events. A failed disposal is not proof that all OS resources closed; fresh acquisition after that settled failure must not be reported as a clean handoff. Host shutdown and startup-failure cleanup include the registry. These are source call sites; the host server is not launched by controlled validation. Registry tests use the actual class with controlled watch IO; a disposable Git/SQLite test exercises `HostWorkspaces` discovery, nested sharing and session-file retargeting. They do not exercise OS watches, public subscription endpoints, live renderer retain/release, or physical clients. The socket transport below now exposes the API; desktop and renderer observer lifecycle integration remains required.


Initial repository setups are serialized per host. A queued entry with no remaining subscriber does not start watching. If the last observer normally aborts during an already admitted setup, that setup may finish under its still-current catalog owner; another subscriber arriving before the final refcount decision reuses it. With no new subscriber, setup completion triggers disposal. Observed catalog-owner loss and host shutdown retire it immediately instead of permitting a lost owner to finish or revive. Publication remains limited to active subscribers throughout. Controlled queue/rejoin and zero-subscriber loss-return tests cover these source lifetimes; this is not OS scheduling or renderer observer timing proof.


## Authenticated event-socket ownership

Hosts advertise `repositoryWatches.version = 1`. An authenticated `/v1/events` connection accepts version1 `repository-watch` messages with its exact host ID, a connection-local subscription ID, one catalogued project/session target, and `retain`, `inspect` or `release`. No raw path grants ownership. Existing upgrade authentication remains required; the peer also rechecks current socket membership and device policy at admission and after acquisition. Revocation retires its requests synchronously, before waiting for socket closure. Workspace invalidations continue through the existing durable workspace events; watch status frames have no event sequence and are not replayed.

A repeated subscription ID cannot change target or reacquire after release/failure. Inspection never acquires. A fresh ID is needed for deliberate retry; reconnect creates a new connection-local domain. Unknown release records a tombstone, preventing later reuse on that socket. The transport limits each connection to128 acquiring/retained/releasing subscriptions and2048 total identities, with the existing1024-byte incoming frame bound. These limits are app transport policy, not measured reference defaults. Clients must recognize the capability before sending; an older host's silence is not readiness.

`pending` means acquisition is outstanding. `ready` means its initial attempt settled; optional `error` separately reports degraded coverage or a retired catalog lease. `inspect` reads this current error without refreshing or acquiring. `release` marks the request retired and aborts its observer immediately, then drains acquisition and lease disposal before reporting `released`. Disposal failures remain visible in that status and connection cleanup. Socket closure, revoked access, send failure and host shutdown drain late resources; the existing registry owns sharing and catalog identity. Only that connection's observer leases are released. No durable event replay restores a subscription.

Controlled tests exercise the actual request parser and peer class, including pending duplicates, release-before-retain, held acquisition, permission loss, wrong owners, delivery failure, bounds and disposal errors. Two peers use the actual registry with injected metadata IO to prove sharing and independent release. The server authentication/binding/shutdown call sites are source/typecheck evidence only: no server, socket, OS watcher, native helper, renderer or retained application was launched. Desktop/preload transport, reconnect generations, renderer observer retention/readiness and live-query scheduling still require implementation and their own acceptance. This source delta does not establish physical or whole-app parity.


## Desktop connection prerequisite

`RepositoryWatchConnection` now retains logical desktop observers independently from a socket's wire IDs. It admits no wire request until a same-host state frame explicitly completes replay and advertises version1 support. Replay-only snapshots cannot authorize initial acquisition. After that first capability decision, every same-host state update is checked, including ordinary live frames without replay completion. Dropping or changing supported capability (or gaining support after an unsupported decision) invalidates readiness and requires a fresh connection; a matching update neither reacquires nor regresses readiness. Unsupported hosts produce an explicit unavailable state. Matching pending/ready/error statuses are validated against host, subscription and target; old socket callbacks and released/unknown IDs cannot attach readiness to a replacement observer. Readiness keeps partial-coverage errors visible. A failed wire does not silently reacquire within that connection.

Disconnect invalidates all readiness while retaining logical observers. A replacement connection waits for its own fresh capability snapshot and assigns new wire IDs. Inspection only reads an already admitted wire; release before readiness cannot turn into a later retain. Disposal releases this controller's observers without closing a shared event socket. The observer and per-connection identity bounds match the host protocol. These are module semantics, not a live connection claim.

The controller and validated status parser remain an additive prerequisite: main event dispatch, authenticated endpoint selection, window/main-frame ownership, preload IPC and renderer retention/readiness are not yet consumers. Their wiring must retain the same connection handles, explicitly deliver fresh state/status/disconnect events, and release window owners on navigation or renderer loss. Controlled client tests and an in-process actual peer/client exchange are not WebSocket, Electron IPC, OS connectivity or native watcher proof. No application, host-service or native watcher process was launched to validate this layer.


## Main/preload window bridge

The desktop main process now owns one connection controller per host event stream. It forwards same-host state frames and unsequenced watch statuses to that exact socket handle, reports error/close immediately, and retains the existing endpoint verification and reconnect path. Watch protocol responses do not advance durable event cursors. A missing capability remains explicit; no HTTP polling fallback acquires watches on an older host.

The trusted main-frame IPC entry accepts the shared retain/inspect/release envelope and publishes status only to its owning window. `RepositoryWatchWindows` binds that logical ID to its original host/target and renderer lifetime before endpoint lookup. It rechecks the lifetime and captured frame after lookup and after creating the observer, including synchronous renderer loss during notification. Unknown inspection is read-only; unknown release records a tombstone; duplicates do not retry failed lookup. A fresh ID permits deliberate retry. Each window has128 logical observer slots and2048 lifetime identities, with released IDs unavailable for reuse until a new window lifetime.

Cross-document navigation retires ownership immediately; only completed document load issues a fresh window token. Preload caches that token within its document, and every request must match it as well as the original trusted main frame. Requests from the outgoing document cannot acquire a replacement lifetime while navigation is pending or after load, even if a frame object is reused. Same-document navigation retains the existing token. The readiness handshake waits without allocating an observer and rejects on another navigation, renderer loss or timeout. Renderer loss/destruction/closed and application quit retire ownership. A late endpoint result cannot create an observer in the successor lifetime. Releasing one window leaves other windows' observers and the shared socket intact. Main checks that the selected endpoint still has the requested host identity before connecting. Preload exposes the request and removable status subscription; renderer consumers must subscribe before retaining, match all status ownership fields, and explicitly release when their query observer ends.

Main/preload call sites are source/typecheck evidence, not executed Electron IPC or WebSocket proof. Controlled tests exercise the actual window owner with the actual connection controller and held lookup/frame predicates. They preserve prior client/peer coverage without launching a native watch or app. Renderer query integration, observer delay/readiness/error/retry UI, native frame/navigation/reconnect delivery and physical acceptance remain required. Existing production socket/client/setup reviews are separate; no aggregate acceptance is inferred.

## Renderer observer retention prerequisite

`RepositoryWatchRetention` owns a host/project-or-session subscription for its enabled query observers. Construction does not acquire. The status listener is installed before retain dispatch; completion of the IPC invocation is not watch readiness. Matching status retains partial-coverage errors. Host/target/ID checks and retired ticket identity prevent late delivery into a replacement owner. Ordinary query controllers keep their own cached/one-shot data; this module does not block those reads or implement the live-query result stream.

The last observer starts the reference's250ms grace; reappearance cancels it without allocating another subscription. Owner disposal bypasses the grace. A failed registration ends its listener and retries after1000ms while observed. A new logical ID is admitted only after main acknowledges release of the old ID. If release is rejected, that same release is retried; uncertain ownership cannot silently overlap a fresh acquisition. This acknowledgement is main's logical retirement, not proof that the host has completed OS resource cleanup. Normal disconnect/unsupported statuses remain with the main connection owner for reconnect, avoiding a second competing reconnect policy. An absent bridge reports unavailable support, without inventing a watch.

The branch hooks and WorkspaceState now consume this renderer lifetime owner as described below. Exact live-query cache identity, result scheduling and query failure recovery remain required beyond this retention integration. The pinned250ms/1000ms constants apply to the reference's whole live-query subscription; this app module implements only the watch-retention side and must not be counted as a complete replacement of that stream. Controlled tests use the actual retention/window/connection classes and injected bridge responses/timers. They do not exercise React, Electron IPC, live sockets or native watcher behavior.


## Branch query watch consumers

The checkout inventory, retained starting-state inventory and nonempty branch search hooks now acquire through one WorkspaceState-owned retention controller in a committed layout effect. Inactive or abandoned renders do not acquire. The starting-state hook uses its existing ever-open/applicability owner, so popup close alone keeps inventory and watch retained; changing owner/mode or unmount releases the observer. Multiple hooks for the same WorkspaceState share one watch, and the existing250ms final-observer delay permits a brief same-owner reappearance. A standalone file cannot grant a repository watch. WorkspaceState stop/start is a reusable connection lifecycle, not permanent query-owner destruction; it leaves still-retained query observers intact. Internal watch retirement followed by failure produces one query invalidation, not two.

WorkspaceState keeps watch readiness/error separately from ordinary query results. A first ready transition triggers the existing repository-invalidated generation, forcing a post-watch read even if an ordinary initial read finished before setup. Observed readiness loss/failure also invalidates that generation; duplicate same-state delivery from multiple retained hooks does not double-invalidate. Existing controllers discard stale responses and serialize replacement reads. One-shot/cached results remain available when watching is unsupported or recovering, with an explicit live-update warning in the two branch menus. Warnings do not waive owning-host connectivity or mutation guards.

Controlled tests exercise actual hooks with explicit commit phases, actual WorkspaceState/retention/controllers and an injected bridge. Other existing component tests use counted watch leases only; those are not transport proof. No mounted React/DOM/native/IPC or screenshot evidence is claimed. Change-specific branch routing is implemented in the later section below. Pinned method/params/common-directory query caching, worker shared live-result streaming, local100ms refresh coalescing and full recovery remain separate requirements. The existing source watch/bridge/capability reviews keep their own boundaries.


## Root-scoped metadata ownership

Each joining catalog target still discovers its own root and revalidates its owner before joining. Sharing uses root within an already host-local registry; it does not equate roots merely because common metadata matches. Discovery completion determines the first established entry, not request arrival order or an atomic filesystem lease. A closing entry drains before a replacement rediscovers current paths. Retired callbacks cannot publish into the replacement.

The captured path tuple stays fixed, but HEAD classification must remain live. A current authorized owner's matching metadata read supplies its latest symbolic HEAD. If that reader discovers a different tuple for the same root, the entry retains its original paths and uses unknown HEAD (`undefined`), conservatively treating local-ref changes as HEAD dependencies. Known detached HEAD (`null`) remains distinct. A later final-release/reacquire may adopt the new metadata. Read failures still report degraded coverage through the existing recovery path; captured paths do not prove coverage of a later replacement repository.

Controlled root-sharing, creator-release, fresh-HEAD and held-close tests use injected metadata IO. The existing disposable Git/SQLite host case remains distinct from those controls. No native watcher, service, socket, renderer, physical repository replacement or whole-live-query parity is established by this source change.

## Change-specific branch refreshes

Watcher metadata kinds now travel through HostWorkspaces and the existing durable workspace event as optional `repositoryChange`. Generic mutations and coverage recovery omit the kind and retain full invalidation. Older clients ignore the additional field; current clients treat an absent or unknown kind as full invalidation. Host and exact project/session matching happen before any version changes.

WorkspaceState keeps query-specific versions alongside the existing global admission version. Recent branches depend on config/head/local refs/remote refs; default/base depend on config/head/remote refs; branch search depends on head/local refs/remote refs. Index/topology/working-tree/synced-branch notifications do not refresh those query results. The metadata watcher still produces its existing six kinds; defining the other two pinned kinds does not implement their filesystem producers. Starting-state search uses the same branch-ref dependency policy as checkout search, an explicit adapter choice.

Recent and default/base reads now have independent in-flight slots and generations. A ref-only event can refresh recent names without canceling or waiting for an unrelated base response. Repeated changes coalesce a latest replacement for each method. Connection loss and explicit retry remain owned by their existing controllers. Observed HEAD/branch changes still refresh inventory even without watcher support; changing only the index-derived revision does not. Search data can remain current on an index-only event while an outstanding exact checkout lookup is invalidated by the separate global admission version.

Controlled tests exercise the actual workspace event consumer and query controllers, plus existing HostWorkspaces with disposable Git/SQLite and injected watcher IO. Server publication and client transport are source/typecheck only here. The pinned source matches live queries by host/commonDir/root and shares method/params results, with local100ms scheduling; this target-bound adapter does not yet establish those cache/stream semantics or native delivery. No app/host-service/native watcher launch occurred.
