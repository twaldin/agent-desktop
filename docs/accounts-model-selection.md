# Session account selection

The composer’s model menu and Accounts settings share the current native session’s OAuth account choices. Stored API keys remain manageable in Accounts, but are not offered to the native OAuth pin API. Provider and model come from that session, not a draft model or a global active-account preference. Native account labels retain organization scope, so two accounts with the same email remain distinguishable.

A read returns a transient worker-owned selection revision and exact model identity. New UI copies this token into pin/release requests. The native bridge binds its original AgentSession, observes model changes (including same-model ABA), revalidates authentication, checks the captured model/revision after asynchronous reads, and rejects stale or busy selections before mutation. Worker protocol 54 refuses older workers; an older host response without a token remains readable but disables mutation. Original legacy requests without a token remain accepted by the optional envelope for compatibility.

Pinning changes the live native choice and records the native credential preference in session history. It does not rewrite a model/provider or other sessions. A flush error remains an error after applying the choice; the UI does not replay it. Releasing clears the live session choice for the next native selection. It does not remove saved accounts or permanently erase the historical preference, which can return on resume.

The renderer owns one host/session/model view. Connection loss and disposal invalidate pending reads and mutation receipts; readable account metadata is retained, writes disabled, and reconnect requires a fresh read. Failed actions require refresh and a fresh deliberate choice. Accounts and the composer receive credential-free invalidations, not replicated secrets. Escape closes the composer popup and restores its trigger even when an account operation disabled the focused button.

Validation uses isolated native AuthStorage, WorkerRuntime, authenticated host HTTP and actual App/Electron interaction. Disposable OAuth-shaped credentials are seeded locally; no provider requests, new sign-ins, personal account changes or quota rotation occur. The separate existing Accounts component fixture controls login URL/manual-response, cancel/error, removal confirmation and refresh/owner-loss behavior. It is not proof that every provider’s live OAuth callbacks work. Provider extension registration, remote-machine physical behavior and all-provider live authentication remain separate acceptance work. No native package, dependency or model version changed.
