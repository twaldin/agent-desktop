# Native OMP browser integration

Source investigation and isolated feasibility experiment, 2026-09-05. **No production browser panel or full browser parity is claimed.** The initial investigation read installed package source, the preserved Codex archive, and official Electron/CDP documentation. The later bounded experiment below opened only its own disposable native browser/profile and localhost page. Neither stage inspected live Codex or other apps, changed installed settings, accessed existing browser profiles, or made provider requests.

## Release 17 metadata transport

The maintained project now selects a small, pinned Bun patch for OMP 18.1.10. `listTabsForOwner` returns immutable snapshots from the native supervisor's actual tab map, filtered by the native session's exact identity. Its original source hash and isolated real-browser proof live under `patches/omp-18.1.10/browser-metadata/`; the selected package patch is `patches/@oh-my-pi%2Fpi-coding-agent@18.1.10.patch`. Host packaging includes the selected patch in its hashed file inventory so a frozen production install reproduces it. Global OMP installations and release 16 bundles are unchanged.

Worker protocol 6 adds a read-only metadata request. `GET /v1/sessions/:id/browser-metadata` uses the existing host authentication and an explicit expected-owner header. Observation never starts a missing native worker. Responses distinguish not-started, unavailable and a running worker snapshot, and name the native target IDs, backend, title, URL and viewport. Desktop parsing validates those fields and their owner/protocol before exposing them. Older route-level 404 responses remain an explicit compatibility case.

The exact-path native test creates a real provider-free OMP worker and reads its empty tab list through the production route class, checking the returned worker PID. A separate isolated test opens a real native browser tab and verifies its target, owner isolation and immutable metadata. Together these establish the metadata seam; they do not establish a renderer stream, input delivery, real tab transport over Tailscale, or a browser panel. The next implementation must still attach to that exact target, keep detach separate from close, and prove shared document state. Worker startup failures from Bun's filename-filter test mode are documented in [test runtime](test-runtime.md), not treated as an authentication limitation.

Installed release 17 verifies the exact patched supervisor hash on Home, Work and Deckbox. Home and Work return actual running worker snapshots with zero tabs; wrong-owner/stale requests fail with 409. Home additionally verifies unauthenticated rejection and no-store responses. Deckbox runs the exact-path HTTP/native-worker tests against isolated archive sources and installed dependencies: five tests, 18 assertions, no provider calls. These checks do not establish nonempty tab streaming across Tailscale. Evidence: `.data/ui-acceptance/home17-installed-contract.json` and `installed-hosts-release17.json`.

## Recommendation

Use **the exact browser target OMP controls**, on the session's owning host, and display that target in the Electron panel through a host-side CDP frame/input bridge. The panel is a new viewer/controller for the same live document, cookies, page history, and JavaScript state. A second Electron view loading the URL creates another document; it does not meet this requirement.

OMP supplies browser automation and ownership machinery, not an embeddable desktop browser widget. Its native backends are Chromium/Puppeteer, an existing browser/Electron CDP endpoint, the Chrome relay extension, and cmux WKWebView surfaces. The first vertical slice should join **native OMP-created Chromium tabs** to the panel, prove actual shared target identity and input, and then add existing-browser backends through explicit capability gates. cmux has a different transport and must stay visible as an unsupported live-stream backend until separately implemented. These are proposed slices, not exclusions from the goal. [O1, O2, O7, O10]

The important correction to an earlier assumption is that **our SDK workers do not currently get OMP's shared browser broker automatically**. Native `registry.ts:176–184` selects that route only for a compiled OMP binary or a declared self-dispatching CLI worker entry. `pi-utils/src/worker-host.ts:11–29` explicitly excludes ordinary SDK embedding; our worker entry does not declare one. Therefore the current default path is a per-process launch with a temporary profile. Adding the declaration alone would be wrong: that entry must actually dispatch all native worker selectors. [O2, O5, A1]

### Other backends

**Connected/spawned browser:** `cdp_url` accepts HTTP discovery, not a `ws://` debugger URL. Native attachment has no default viewport override and may adopt a user-visible page; `open({url})` navigates it. Spawned `app.path` can point at an Electron executable; reuse detection refuses an already-running application without a reusable CDP endpoint instead of starting an isolated impersonation. The app should expose exact, explicitly selected targets, with detach and close distinguished. A CDP viewer can in principle observe these targets, but lifecycle, dialogs, focus and permissions need separate proofs. [O2:154–215,256–305; O9:179–220,239–297; O14:25–30]

**Relay:** the native Chrome extension uses `chrome.debugger`; the loopback server exposes `/json/version`, `/json/list`, `/cdp` and `/ext`. Default URL is `http://127.0.0.1:9224`. The machine-global relay daemon auto-starts only in supported CLI-worker mode; SDK embedding requires an already-running endpoint. `/cdp` rejects browser Origin headers; `/ext` accepts extension origins and checks a token only when configured. Discovery/auto-attach can inspect multiple eligible user tabs, even though explicit drive claims govern grouping. The bridge forwards page commands, suppresses `Browser.close`, acknowledges `Browser.setDownloadBehavior` without implementing a download path, and rejects browser-context creation. Do not assume every Chrome domain is available through `chrome.debugger`, or that another debugger/DevTools cannot interrupt it. Relay screencast, selection and reconnect behavior remain untested here. [O2:216–253; O10; O11:17–40; O16:57–108; O17:530–571,640–750]

**cmux:** selected through `CMUX_SOCKET_PATH`, optional native socket password, and `PI_BROWSER_CMUX`/setting state. This uses cmux RPC and WKWebView surfaces, not a Chromium CDP target. It can create or attach a surface; native cleanup closes only one it created. Its screenshot API captures the viewport, and explicitly reports full-page/element-crop limits. Native upload reads files on the session owner and transfers file data to that surface. A Chromium stream implementation cannot honestly claim cmux support; a bounded screenshot/control adapter would be a separate lower-frame-rate backend until a native streaming API is established. [O10:183–199; O3:420–488,648–679; O18:552–578,715–724]

| Electron offscreen `paint`/shared texture | Only for WebContents already owned by that Electron runtime | Produces bitmap or GPU texture output from Electron windows; it is not an API to import an external Chrome page. GPU texture consumption adds native integration. [Electron offscreen rendering](https://www.electronjs.org/docs/latest/tutorial/offscreen-rendering) |
| Copy DOM, iframe the URL, or proxy site HTML | No | Duplicates or changes page/security/state semantics and does not meet the shared-tab requirement. |

CDP `Page.startScreencast` emits compressed frames with metadata/session IDs; `Page.screencastFrameAck` acknowledges them. The method is experimental. Use one host-side producer per target and bounded latest-frame fan-out, so one slow viewer cannot stall every client. Probe actual browser/protocol support rather than relying on newer tip-of-tree options. A screenshot fallback must be labelled and measured, not reported as a live stream. Navigation/back/forward/reload can use target-scoped Page methods. [CDP Page](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-startScreencast)

Translate explicit pointer/key/text/composition events against the **accepted target viewport and frame generation**. CDP has mouse/key dispatch and experimental text/IME commands; that does not establish complete clipboard, selection, accessibility, drag/drop, native menus, audio, downloads or WebAuthn behavior. Two viewers cannot independently resize the same page without changing each other's document geometry. Prefer one shared viewport, scaled/letterboxed locally, plus an explicit revisioned resize control. [CDP Input](https://chromedevtools.github.io/devtools-protocol/tot/Input/)

## Ownership, permissions and transport

1. **Owner is the existing app session host.** `(hostId, sessionId, nativeTabName, workerGeneration, nativeTargetId, browserInstance)` must resolve server-side. Browser targets and profiles stay there. A saved catalog identifies actual tabs; it must not claim a dead target is still attached because a URL happens to match. Parent-owned source currently has no browser transport contract; the existing worker API and renderer window are the integration points. [A1, A2]
2. **Renderer reconnect is different from host restart.** Persist tab associations, selected tab, order and last-known URL/title, but revalidate exact live identity before sending input. Renderer detach/reconnect should preserve all document state while the owner lives. Current native session disposal closes its owned tabs; preserving exact tabs through a host restart needs a deliberate cooperating lifecycle/broker change. Profile persistence can preserve site storage, not an arbitrary live document. Native orphan records are cleanup records keyed by process/target, not a resumable session-tab database. [O3, O4, O13, O19]
3. **Native agent approval stays native.** The browser prelude declares `approval:"exec"`. `invokeEvalPrelude` resolves live `tools.approvalMode`/`tools.approval`, waits for the real UI Approve/Deny selection when required, and rechecks replacement/disable races. Do not call the private handler to bypass this path. Direct human navigation/input needs an explicit UI action receipt and ownership checks; it must not fabricate an agent tool call or permission approval. [O1:141–152; O20:77–132]
4. **OMP does not supply Codex-equivalent per-origin policy here.** The seven browser settings and execution approval do not define separate site-history, upload, download or full-CDP consent policies. Raw native `tab.run` can reach Bun/Node and arbitrary Puppeteer operations; a UI-only domain allowlist cannot honestly enforce those agent restrictions. Such restrictions require enforcement in the actual native execution/network boundary. Current launch defaults also include `--no-sandbox` and optional proxy/certificate flags; do not describe them as a Chromium security sandbox or silently change the configured policy. [O12; O14:18,54; O5:436–457]
5. **Keep CDP/relay private to the owner.** Reuse the app's existing authenticated loopback and same-user Tailscale transport. Browser page JavaScript must not receive host bearer credentials, debugger endpoints, relay tokens, raw CDP send methods, filesystem paths, or the desktop preload bridge. The current app rejects Origin on remote requests, authenticates the socket peer, and its own renderer is sandboxed with isolated context and denied window navigation. The new page stream crosses main/preload as bounded data, not remote HTML inserted into app chrome. [A2:415–440; A3:430–440; O16:57–108]
6. **Same-tab actions need conflict behavior.** Native `runInTab` currently rejects a second run while busy. A raw second CDP controller could otherwise interleave with native agent automation. Start with truthful native-busy rejection for competing mutations and a small revisioned active-controller lease for human input; observation may continue. Implement human takeover only once cancellation of the specific native browser operation is proved. Do not release a tab or abort an entire conversation as a hidden substitute. Unexpected transport loss after a click is uncertain; never replay clicks/typing automatically. [O3:494–520,618–646]
7. **Page-origin actions remain page-origin actions.** Preserve normal site navigation, redirects and subresource behavior on the owner. Treat `http://localhost` as owner-local. Download/upload and external protocol/file URLs need typed owner-side operations and bounded transfers; do not route arbitrary renderer file paths or relabel desktop-local files as owner-local. Web permissions, popups and JavaScript dialogs need surfaced state, including native agent auto-dialog policies when configured. No browser state clearing or credential sharing is implicit in opening a panel. [O1:69–78; O8:1092–1107; O18:715–724]

## Small implementation contract and ordered proofs

Proposed implementation names below are **not existing APIs**:

```ts
// Pure shared metadata. All native handles/endpoints remain in the owner worker.
type BrowserTabInfo = {
  id: string; hostId: string; sessionId: string; name: string;
  generation: string; revision: number;
  backend: "headless" | "spawned" | "connected" | "relay" | "cmux";
  state: "opening" | "ready" | "busy" | "closed" | "lost";
  url: string; title: string;
  viewport: { width: number; height: number; deviceScaleFactor: number };
  capabilities: { stream: boolean; pointer: boolean; keyboard: boolean;
    text: boolean; composition: boolean; resize: boolean };
};
// Worker adapter: list/subscribe native tabs; attach/detach a viewer;
// typed bounded navigation/input/resize, revision checked; binary frame delivery.
// Opening/closing use native operations and emit actual lifecycle acknowledgments.
```

Keep a single small pinned adapter in `apps/host/src/omp-browser/**`, narrow additions to the existing session worker protocol/runtime, and a host-owned `browser-http.ts`. Add pure shared browser types, existing main/preload transport bindings, `BrowserPanel.tsx` and its state/CSS, and small App panel integration. Persist catalog metadata through the existing store only when persistence behavior is defined; no frames, page contents, keystrokes or cookies in the command/event journal. Existing old hosts should return an explicit unsupported capability, with authentication/network/backend failures retained as failures. No general CDP proxy, new orchestration framework or page-state replication service is needed.

The smallest upstream change is an explicit owner-filtered tab enumeration/lifecycle subscription and exact-target attachment/control seam. It must include agent-created tabs, title/navigation updates and disposal, rather than only tabs opened through the UI. Prefer that maintained patch/export over production use of `getTabsMapForTest`, method monkeypatching, or intercepting textual tool output. Native browser execution remains the authority. The exact SDK `ToolSession` is assembled inside `createAgentSession`; the experiment successfully invoked the existing `session.getToolByName("eval").execute(...)` path and its real browser prelude without reconstructing it. That provides a real native open/action path for a first adapter; it does not supply a typed desktop catalog, lifecycle subscription, streaming or input contract. [O3; O7; O21:1787–1940; O13:5034–5041]

## Actual isolated native/CDP feasibility result

The maintained [native-browser.ts experiment](/Users/twaldin/dev/agentic-app-expiriment/scripts/acceptance/native-browser.ts) passed **seven actual native/browser phases** on macOS arm64 using Bun1.3.14 and the already-existing Chrome for Testing **150.0.7871.24** executable. No download was needed. The final verified run took approximately 2.7 seconds from parent invocation to completed native cleanup. Evidence is private under [.data/native-browser-acceptance/2026-09-05-verified/result.json](/Users/twaldin/dev/agentic-app-expiriment/.data/native-browser-acceptance/2026-09-05-verified/result.json), with source/binary fingerprints in [invocation.json](/Users/twaldin/dev/agentic-app-expiriment/.data/native-browser-acceptance/2026-09-05-verified/invocation.json).

```sh
bun scripts/acceptance/native-browser.ts .data/native-browser-acceptance/new-run
# An existing compatible Chrome for Testing executable can be supplied as argument 2.
```

The parent spawns an isolated Bun child with temporary HOME/XDG/TMPDIR, no inherited credential variables, an explicit existing browser executable, and external fetches rejected. The child creates a **real native SDK session**, obtains its actual Eval tool, and calls the native browser prelude. It uses `getTabsMapForTest` solely to locate the native-created tab for this labelled experiment; that accessor is not an accepted production seam. No browser or native SDK function is mocked, no provider is called, and no artificial user/tool transcript entries are inserted.

| Phase | Actual evidence |
| --- | --- |
| Native open | Native browser prelude opened the localhost fixture through a real tab worker. Creator session ID matched the real native manager; backend was the expected SDK process-local headless browser with a profile under the isolated tree. |
| Second CDP observer | A separate Puppeteer/CDP connection discovered the **exact native target ID**, then read the same URL, page-generated random identity, cookie and unsent field value. The proof selects by target ID, not title/URL matching. |
| Native action → observer | Native `browser.tab(...).click` changed the counter from 0 to 1, observed through the second connection. Native and observer PNG screenshots were byte-identical at each stable state, and the hash changed with the counter. |
| Observer input → native | Raw `Input.dispatchMouseEvent` press/release on the observer CDP session changed the same counter to 2. Native browser evaluation independently asserted the original document identity and new counter. Every native Eval cell was required to complete with exitCode0. |
| Native frame stream | Actual `Page.startScreencast` produced a PNG frame with 800×600 native viewport metadata; `Page.screencastFrameAck` succeeded. The saved frame was visually inspected and showed the actual counter2/unsent field. This establishes a working native producer, not stream latency/backpressure or multi-view acceptance. |
| Observer detach/reconnect | Disconnecting the observer left native browser control working. Native clicked again to 3; a fresh observer connection found the same target, original random document identity, cookie, unsent field and Chromium process. Four native/observer screenshot pairs for counts0–3 were identical within each pair. |
| Native cleanup | Real `session.dispose()` removed its tab registry entries, disconnected the native browser, exited its owned Chromium process with code0 and removed its temporary Chrome profile. The isolated child also exited0; the parent removed the remaining isolated profile tree. No manual kill was needed. |

Final experiment source SHA-256: `f90608c85606a79803a62d46c7387cd459f93dcef6c278034ea290367c03d294`. Package version and four critical native browser file hashes were asserted against the exact release before and after execution; the experiment source was also unchanged during the run. Earlier first/final runs remain separate evidence, before strict per-cell status and source-stability assertions were added. Focused typecheck and diff checks passed.

This makes the **same-target CDP approach experimentally viable**. It also confirms the SDK temporary-profile/disposal caveat. It does not prove a production Electron panel, two viewing desktops, Tailscale streaming, concurrent native/human input arbitration, persistent host-restart adoption, Linux packaging, relay/cmux support, WebAuthn, uploads/downloads, clipboard/IME or full browser UI parity.
