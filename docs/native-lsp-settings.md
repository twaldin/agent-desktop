# Native language server configuration

OMP settings → Language servers inspects the selected host and admitted project through the existing authenticated discovery worker. It exposes built-in definitions, configured overrides, disabled servers, missing commands and root markers, and native TypeScript server selection. Reading configuration never starts a language server. Saved changes apply to new sessions; existing workers are not reconfigured.

The pinned OMP 18.1.10 inspection API reuses its source ordering, normalization, shallow per-server merge and applicability filter. It includes all six visible/hidden JSON/YAML variants at the project root, native project/user config directories, plugin and marketplace sources, and home fallback. Native source enablement and profile directory behavior remain authoritative. In particular, native LSP config directories are not inferred from the settings storage directory.

Each source has a server-issued identity and revision. The UI can edit admitted local files, create a user or project override, toggle Disabled, remove an override, and set or remove idle timeout. Native fields use structured controls, including advanced timings, capabilities, initialization options and settings. Free-form nested values are limited to fields where native types are broad. Unknown saved fields and aliases are preserved. Plugin and built-in sources are read only; use an explicit local override. Removing differs from disabling and can reveal a lower layer.

Reads retain native effective fields with per-field source attribution. Binary paths, root matches, runtime client factories and PID substitution are derived read-only information. Source precedence is shown highest first. A higher source can shadow the edited value.

Malformed or unsupported documents are not writable. Saves compare the original complete configuration revision, serialize writers with the native file lock, and atomically replace a private sibling file after a final check. These checks detect observed external edits; they are not a filesystem transaction against an uncooperative writer during the final check/rename interval. JSON/YAML values are preserved, but serialization can change document formatting and remove comments. Symlink sources are read only or rejected; HTTP clients cannot supply arbitrary file paths. Drafts survive errors, refreshed conflicting catalogs and disconnects. Explicitly reviewing the latest source revision retains draft edits while adopting unrelated current fields.

`bun run test apps/host/src/integrations/lsp.test.ts apps/desktop/src/renderer/lsp-settings.test.ts` exercises disposable native files, the real loader oracle, authenticated HTTP and the actual discovery worker, plus renderer revision and connection fencing. `bun scripts/acceptance/lsp-settings-app/run.ts OUTPUT` runs the production App against a disposable authenticated host and native discovery worker with synthetic Electron/DOM input. It records real rendered geometry and captures; it is not official Codex visual parity, live-provider or physical-machine acceptance.
