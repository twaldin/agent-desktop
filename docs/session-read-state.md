# Session read state

The Sidebar uses an explicit read cursor for each original host and session. Assistant message completion, turn completion and a new extension interaction request advance a durable activity cursor. Title, model, user-message and tool chatter do not. The host commits the event and session cursor in one SQLite transaction, then publishes the cursor with its runtime/interaction event. Existing sessions without a cursor start read; modified dates do not infer unread activity.

Read marks use the existing replicated preferences and durable command receipts, keyed by the original host/session UUIDs. A mark captures the activity already seen before sending. New output during a held acknowledgement remains unread. An uncertain acknowledgement retries the original command ID. A rejected pre-admission action has no receipt to retry; its error can be dismissed and the user can make a new deliberate selection after reconnecting. Remote-host cached rows can be marked through this device's connected local preference replica. An unavailable local replica reports failure rather than claiming a saved change.

Automatic reading requires the selected conversation to be visible, the application document to be focused, and a successful transcript read covering the current activity cursor. Loading or older cached messages cannot acknowledge new output. Explicit Mark as unread remains until new content arrives or the user leaves and returns to the view. The Sidebar supplies priority ordering and menu actions in its composed flow.

Author checks cover real SQLite reopen/rollback, original host isolation, held and lost acknowledgements, offline boundaries, the actual hook with controlled focus/commit delivery, and catalog projection. The composed Sidebar validation must mount the production hook and exercise its actions, persistence and ordering. Controlled native event inputs are not real provider/OAuth execution, and this OMP event mapping does not establish every Codex notification or automation exemption.
