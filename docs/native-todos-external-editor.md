# Native Todos configured editor

The Todos section offers **Edit in configured editor** alongside the existing structured Markdown editor, copy, import and export controls. It resolves VISUAL/EDITOR in the original worker, uses its cwd and environment, and opens the existing dock terminal. Missing configuration is reported as unavailable.

The prepared document uses the pinned OMP 18.1.10 Todo controller semantics: native `phasesToMarkdown`, its starter text for empty Todos, the `.todo.md` suffix, and the helper's default single trailing-newline trim. A zero exit saves through `NativeSessionTodos.mutate` and the shared native `commitUserTodoEdit`, including unchanged successful files. A nonzero editor exit returns native cancellation. Parse errors do not change Todos; output remains recoverable through the job's uncertain result.

Every request names the original native session, worker epoch and branch revision. The host reserves a durable request and terminal identity before preparing or launching. A second client with the same request inspects the original job; changed input is refused. Newer Todo state, worker loss or a retired owner cannot be overwritten by late editor output. Uncertain native saves and lost receipts are never replayed.

The renderer saves requests before dispatch and reconciles their original status. Hiding the panel, changing conversations or closing the desktop does not kill the host editor. Explicit cancellation joins termination of the original process. Status, cancellation, listing and retained output remain available through the authenticated original-host routes after the source disappears. Recovery prefers completed saved editor output. If a dispatched job becomes unknown before output is recorded, it retains the bounded initial Markdown and labels it as original input. It does not claim to recover an unsaved editor buffer. Input configuration and scratch files are removed after verified termination; normal explicit cancellation still has no recovery result. Recovery only copies text; it never reapplies an old edit. Pending jobs after host restart remain unknown until their original process is inspected or cancelled.

Process execution reuses `plan-editor-process` and `PlanEditorTerminals`, with separate Todo manifests under `todo-editors-v1`. The SQL claim mechanics are shared by typed Plan and Todo wrappers. Plan's existing record namespace, serialized shape, hash, schema gate and public wire contract are unchanged. Todo jobs use `todo-external-editor:v1` metadata and the existing schema 26 gate, with no separate Todo state store. Worker protocol 65 adds private preparation/availability. The editor routes have their own version 1 contract and reuse native Todo mutation semantics; command protocol 22 is unchanged.

Private editor commands, environment values and host filesystem paths never enter the desktop bridge. Controlled tests exercise native controller/helper semantics, actual worker ownership, real private tmux execution, SQLite recovery, HTTP/IPC validation and renderer actions. Native GUI appearance, physical cross-device behavior, packaged-helper acceptance and full Todo/GOAL acceptance remain separate gates.
