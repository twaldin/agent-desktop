# Edited HTML output preview

A completed native turn with exactly one successfully written or edited HTML path can offer that page in Suggested, after the existing file/app and explicit website priorities. The producer reads actual saved `write` resolved paths, successful native `edit` create/update results (including per-file results), and applied `ast_edit` replacements. Failed/deleted/preview-only edits and tool arguments alone cannot create the row. The source icon remains a separate original-host file action.

Opening the row acquires a read-only preview from the original loaded task worker. It captures the output epoch, saved entry, path/revision, current branch and workspace. The browser creation keeps that session and worker; it uses the ordinary saved creation ticket/receipt flow. A queued removal, changed source, lost host/bridge/document or expired admission cannot create a replacement preview. Worker protocol 53 is required; this additive feature cannot run against the previous protocol 50/51/52 workers. Composition must preserve the independently reviewed protocol-52 methods alongside these new operations.

The worker serves a nonce URL on its own loopback interface. The browser runs on that same owning host. It reads only supported successful output files recorded on that captured branch, at most 32 files and 16 MiB total (the existing per-file reader is bounded to 2 MiB). No directory enumeration or arbitrary surrounding project files are served. A maximum of four leases and eight pending reads share one worker-local listener. Each lease expires after five minutes; the renderer derives a conservative local admission deadline from the bounded duration, not the remote host clock. File/workspace checks detect sampled identity and revision changes; they are not an atomic OS filesystem lease.

Captured relative HTML, CSS, JavaScript, images and font paths can load. Relative navigation remains under the original nonce. Unsupported, unrecorded, traversal and changed paths fail closed; JavaScript-generated paths do not add files to the captured map. The response policy blocks connection requests, remote scripts/styles, nested frames, forms and base-URL changes. This is a read-only saved-output preview, not a development server: root-relative links, dynamic HTTP APIs, external dependencies, unrecorded existing project assets and arbitrary full-site behavior are not established by this flow. An already loaded page is not erased when its lease retires; subsequent reads fail.

The desktop document retains each original endpoint through acquisition and release. Late acquisition after document loss is released before refusal. Renderer tab removal/source loss releases its exact lease, while document retirement independently drains releases and retains cleanup errors. A lost acquisition response can leave a worker lease until its bounded expiry; there is no automatic acquisition retry. Reloading the desktop keeps the saved browser identity but does not reacquire an HTML lease or rerun historical tools. Explicitly editing the ordinary browser address starts its normal navigation behavior instead of carrying the preview's admission restriction to another address.

Acceptance uses a disposable actual OMP worker with a deterministic model calling five native writes and one native EditTool operation, then the production App in Electron and an original Chrome target. It covers source inspection, HTML/CSS/JS/SVG rendering, a relative saved page, native Back, missing source, desktop reload and offline state. Controlled tests cover owner/epoch/revision checks, queued refusal, held acquisition/retirement, original endpoint release, dual operation/cleanup errors, bounds and foreign envelopes. Private cloned dependencies and the selected Chrome backend are explicitly qualified; no fresh installer, every browser backend, physical/pixel parity or whole GOAL acceptance is claimed.
