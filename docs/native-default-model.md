# Default model for new sessions

Configuration > Models exposes the native `modelRoles.default` setting for host and project scopes. The selector uses the owning host's native model catalog and writes through the existing revisioned Settings mutation route. Saving changes only future session resolution; it does not change the model or account of an open session.

The control keeps the complete local `modelRoles` map while replacing or removing only `default`. Review, plan, custom aliases, and ordered fallback arrays remain byte-for-value equivalent. A project can inherit the host default, and the host can return to the native fallback. The card distinguishes local configuration from the effective inherited value. Saved unavailable models remain visible, and advanced native values such as fallback arrays remain visible until the user deliberately chooses a single model.

A concurrent Settings write fences the pending edit. The user must review the current revision before saving. The host revalidates the revision and persists through native Settings; no renderer-only model registry or alternate settings API is used.

Controlled source and host tests use a disposable native agent directory and model catalog with no credentials or provider calls. They verify unrelated role preservation, project inheritance, conflict retention, and current-session semantics. A hidden production App run saved a global default, preserved the open session model, selected a project override for a new session, removed it to inherit the global default for another new session, and selected that persisted global default after a cold host restart. The App run uses controlled `auth: none` model definitions and synthetic Electron input; it is not a real-provider, OS-global-input, or reference pixel-parity result. Conflict behavior is covered by controlled state and Settings tests, not by the App run.

The original App screenshots were captured after the local window environment resized the fixture to a 355 CSS-pixel content width. That is below the production window's 720-pixel minimum and is retained only as functional evidence. The corrected acceptance matches the production minimum, records settled bounds, viewport, DPR and zoom with every capture, verifies a wide baseline through owned-window sizing, and separately scrolls the default-model card into view at the supported 720-pixel minimum, asserting that its selector and an action remain visible without horizontal document overflow. These controlled captures do not identify the external window manager or establish reference pixel parity.
