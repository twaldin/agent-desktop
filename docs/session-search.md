# Command menu and stored chat search

The command menu uses existing app actions and a read-only search endpoint on each owning host. Opening the menu does not open an OMP session, start a worker, read account configuration, or call a provider. Cmd+K and Cmd+Shift+P enter the root command menu; the sidebar Search button and the configurable Switch chat command enter its chat view. Cmd+P retains the separate file-search dialog.

`GET /v1/sessions/search` requires the usual host authentication/access policy plus an explicit search-owner header. Query parameters carry a nonempty query of at most 256 characters, a content-search boolean, and a result limit from 1 through 9. The response repeats the owner, version and query. Desktop responses are limited to 64 KiB. A native-window/host request owner aborts the previous search on replacement, explicit dialog cleanup or window destruction; request IDs keep late cleanup from cancelling a newer query. The desktop validates both response ownership and shape; an older host without this endpoint is unsupported, not an empty search result.

Only catalog-owned sessions are candidates, including archived sessions. Metadata matches use the current catalog title. Content matches read persisted user and assistant text from the native OMP journal. This intentionally includes earlier branches and pre-compaction messages for discoverability. Results navigate to the existing session; they do not restore a branch or imply that the snippet is in the current model context. Tool output, thinking and image blobs are not searched by this implementation. Recent and pinned catalog rows in the empty chat view are navigation entries, not proof of a content search.

The reader uses the pinned native JSONL parser, but does not construct `SessionManager`, repair caches, migrate files, resolve blobs, or initialize the SDK runtime. The catalog is the authority for allowed journal paths, including explicitly imported original sessions outside the default directory; no path comes from the search request. A read uses one regular-file descriptor, rejects aliases/hard links, checks native identity and format, and requires unchanged descriptor/path identity before accepting text. Missing, malformed, changing or unsupported journals produce an explicit incomplete-coverage result; private filesystem errors do not leave the host.

The reader streams 64 KiB chunks through the pinned native JSONL parser, retaining one record plus a chunk and at most one result snippet. There is no longer an 8 MiB whole-journal cutoff. It validates all records and the unchanged file identity even after finding a match. Multibyte UTF-8 is decoded across chunk boundaries; malformed trailing records and invalid encoding reject the result. A single large JSONL record can itself use substantial memory, as with OMP's stream loader; this is not a constant-memory claim. Cancellation is checked at chunk/record boundaries, with cooperative yields between parser batches.

Two searches may run concurrently. A search admits at most 256 non-title-matching histories and stops admitting additional histories after 32 MiB or 1.5 seconds. These are **admission thresholds**: an already-admitted journal is streamed in full and may exceed either threshold. Failed reads exhaust remaining byte admission. All catalog titles are considered regardless. A shared ranking function keeps title matches ahead of history matches, then recent updates, on both the host and the federated desktop before truncation. Snippet positions come from the exact raw occurrence before display whitespace cleanup. Coverage describes determining the matching session set, not bytes read: a title hit needs no history scan to qualify.

Full-history search parity remains incomplete. Catalog paging/resumption, query continuation beyond the desktop timeout, very large single-record handling, offline indexing, exact ranking and tool/thinking search semantics remain required work. The current partial-results label does not waive these requirements. Pure tests verify streaming a late match beyond 8 MiB, native title slots, chunk-split UTF-8, malformed tails, cancellation and admission behavior. They do not prove actual file identity/race handling, memory use, HTTP/IPC cancellation, native menu interactions or installed behavior. The launch hold prevents new native acceptance runs; retained apps and sealed references stay untouched.

## Browser-tab search

The root command menu also searches existing browser dock entries across sessions in the current window, including hidden docks. Matching requires every whitespace-separated query word as a lowercase literal substring of title, native page title or URL, preserves window insertion order and shows at most ten entries. It never discovers arbitrary host sessions or creates a browser. App owns the live commands/chats mode used by both the dialog and metadata hook. Existing read-only browser metadata refreshes in commands mode and every three seconds after the previous round settles, deduplicated by owning host/session. A renderer-wide admission queue keeps at most four calls in flight across replacement rounds, bridge changes and hook remounts; an uncancellable old call retains its slot until settlement. Saved/custom dock titles remain separate from live page titles in the matching corpus. Closed menus stop new read admission and ignore late responses; existing metadata IPC cannot cancel an already-sent read. Offline, unavailable or stale native targets retain their saved dock title with an explicit page-details-unavailable label. A different worker, session, host or native target cannot supply the URL.

Selection rechecks current dock membership and the full owner identity, activates the existing right/bottom destination, and navigates only if the owning route differs. It does not create, move or resurrect a tab. Tab and Shift+Tab in the root input cycle only between nonempty chat and browser result sections; ordinary command groups are not part of that cycle. Query changes reset the first-section behavior. Modified Tab, composition and fewer than two result sections retain ordinary handling.

This is a source implementation, not native/browser interaction acceptance. The reference runtime also tracks detached and browser-use-only pages without a dock entry; this application's missing equivalent registry remains required work. Fresh metadata has no durable offline URL index. Actual cmdk focus/selection, polling and late responses across real IPC, same/cross-route selection, detached-window ownership and matching native pixels remain unverified under the launch hold. Pure tests cover matching, owner/worker rejection, window membership, bounded read admission and section-index transitions; they do not simulate a DOM or prove pointer/keyboard behavior.
