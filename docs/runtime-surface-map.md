# Runtime surfaces: environment, goals and changed files

The missing floating card is Codex's **task summary**, separate from its tabbed right/bottom panels. Its rows open or operate those panels; it is not a permanently expanded Git form. OMP supplies useful native state for goals, subagents, titles and approvals, but our current worker projection omits several of those fields. **Goal continuation and native mode restoration remain unimplemented in our headless adapter.** Rendering a goal strip alone would not close that gap.

This bounded trace used pinned static Codex 26.901.41600 and OMP 18.1.10 source plus the three supplied screenshots. No Codex process, provider, installed service or user configuration was operated. It extends [the panel/library trace](panel-reference.md); it does not replace that document's Pierre renderer, docking and terminal contracts.

## Goal strip and changed-files summary

The goal is **P `kjr` (7078993)** in the composer's attached tray, using `s3.Item`/`s3.Row` (row at6337557), not a dock tab header. It presents a native status label, truncated objective, compact elapsed/budget indicator, and icon actions. Clear dispatches the goal-clear operation; pause/resume dispatches the requested native status; editing loads the saved objective and opens the goal editor with owner/task context. Pending actions disable controls; failures remain errors. The editor's save invokes the goal-update path and cleans temporary materialized inputs on rejection.

P `Ejr` (7077310) maps Codex statuses to Pursuing goal / Paused goal / Goal stalled / Goal usage limited / Goal limited / Goal achieved. P `Pjr` (7088865) ticks once per second only while active: displayed elapsed is saved `timeUsedSeconds` plus time since `updatedAt` (Codex timestamp in seconds). Active/budget-limited goals with a token budget show compact used/budget instead. An OMP adapter must convert its millisecond timestamps and preserve its different accounting/status semantics.

The screenshot's “65 files changed +1,528 −173” corresponds to **D `tT` (274395)**, an in-progress turn-diff summary. It receives the turn's `unifiedDiff` or supplied diff summary, computes `fileCount`/added/deleted, and returns nothing when there are no changes. Click calls the Review opener with conversation identity; hover opens an interactive file list whose path rows open the requested review file. D `rT` (277150) is the completed-turn variant: native patch batches, per-file diff results, compact header, initially limited file rows and real expand/review actions. Changes in the Environment row and a particular turn's changes are **different data sources**.

Our [workspace types](../packages/shared/src/workspace.ts) currently expose Git status and a unified patch but no revision-bound numstat summary or turn snapshots. Counting all repository changes and labelling them “Last Turn” would be wrong, especially with pre-existing edits, concurrent agents and writes through bash. Preserve binary/rename/conflict states and distinguish unavailable from zero.

## Smallest cohesive implementation order

1. **Panel presentation:** introduce one local per-window controller for right/bottom tabs and reuse the real WorkspaceState and native terminal controller. Compact pill strip/add menu, draggable separators, close versus hide, file-specific tabs and persisted topology come from [panel-reference.md](panel-reference.md). Keep buffer conflict recovery, Git index/HEAD guards and shared terminal input/grid receipts intact.
2. **Environment + Review:** put owner/branch/Changes and compact Commit in a 300px summary card. Move commit and worktree forms behind their actions. Replace the raw diff `<pre>` with the traced Pierre adapter. Add real owner Git totals; unknown/loading/error stay distinct. Branch switching/push remain explicit backend work, not falsely working buttons.
3. **Native runtime summary:** add a bounded typed snapshot/read operation and invalidations for goal, child roster/jobs, title and native structured edit details. Native records remain authoritative; the app catalog is a projection. Validate actual tool/job lifecycle and restart recovery before implementing the strip/cards against these fields.
4. **Goal execution + remaining surfaces:** separately close native headless mode restoration/continuation with ordered owner admission, pending-input precedence and no uncertain replay. Then connect Sources and actual computer/browser viewing. A visible card cannot stand in for these contracts.

Acceptance must use matching UI states and actual temporary repositories/native sessions: same totals in chip and opened review revision, real staged commit, error/empty/loading states, dock hide/reopen without shell restart, child settle/reopen, manual title synchronization, native goal pause/resume/restart and paired-client approval resolution. This document is a source/design checkpoint only; none of these newly described surfaces is claimed implemented or physically accepted.
