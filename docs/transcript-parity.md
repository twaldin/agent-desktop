# Transcript parity: pinned reference and implementation plan

The original source audit was recorded on 2026-09-05 during the release 6 packaging freeze, without implementation changes or live Codex access. The dated checkpoints below distinguish later implementation, deterministic fixtures and actual installed acceptance; the baseline tables retain the original gaps for comparison.

The baseline remains Codex **26.901.41600 / build 7982**, archive SHA-256 `077cc65356aeae34c5d8b4de0b4cc383f6fb137ed1d69a9b3dfe69ffafa058ab`. Scope and exclusions are defined in [GOAL.md](../GOAL.md). No live Codex process, UI, screenshot, credentials or conversation database was accessed. Local developer workflows apply; hosted sharing, ChatGPT history, voice, pets, billing and cloud execution remain excluded. A shipped component can be gated or reused by another surface; source presence does not prove its default visibility.

## Whole-conversation Copy as Markdown

Conversation actions and the existing `copyConversationMarkdown` command now copy the current native transcript through one operation. The command is configurable in Keyboard settings, with no new default accelerator. Export preserves native display order, the conversation title, quoted user text, assistant Markdown and literal tool/command output. Dynamic fences preserve embedded backticks; missing, truncated, attachment and unsupported content remain qualified rather than being invented. Hidden reasoning and provider-only metadata are not exported.

The snapshot carries explicit host/session ownership and host-versus-cache provenance from its captured read. Empty, loading, failed, cached-only or disconnected transcripts remain unavailable. The operation captures its payload before awaiting `navigator.clipboard.writeText`, refuses overlapping App clipboard writes without replay, and reports success only after fulfillment. Navigation fences late success or failure feedback. A pending write blocks another attempt until it settles, with an explicit wait reason even after switching conversations. Copying neither submits a prompt nor changes journals, files or composer drafts.

The pinned source places this action inside a Copy submenu; the current App exposes it directly in its existing Conversation actions menu. That is a bounded command implementation, not full menu or pixel parity.

Original Work candidate `6bc882e` validation: typecheck/build and 16 focused tests with 120 assertions pass. This is Work evidence, not a native run of the Root-composed source. The isolated production App exercised menu, configured-key and command-menu copying, loading/read refusal, empty and changed owners, clipboard rejection, and late completion. Eleven CG window captures are qualified at 1440×1000, DPR 2 and zoom 1 with native display-mode, AX/window, theme/font and Space checks. Real disposable SessionManager journals, a retained file and exact draft revisions remained unchanged; no host command mutation or renderer error occurred. Both owned processes exited 0 and the successful fixture was removed.

Root integration corrects the fixture to read Electron 44’s console-message details object and fail on recorded renderer errors. That fixture correction has no new native execution; the original Work run’s empty error array does not establish renderer-error absence.

Clipboard fulfillment/refusal is controlled at the API boundary: no system clipboard content was read or written, and OS clipboard integration is not claimed. Provider execution, installed-release acceptance and matched reference pixels remain unverified. Unavailable-model and projectless task-location diagnostics are retained in the fixture evidence. Reproduction: `scripts/acceptance/conversation-markdown-app/run.ts` with the explicit `CONVERSATION_MARKDOWN_CLIPBOARD_BOUNDARY=controlled-api` flag; private originals are in `.data/native-app-002/`.

## Ordinary code-block toolbar and highlighting — 2026-09-07

Fenced code now uses the pinned ordinary code toolbar: a language glyph and human-readable label, icon-only wrap/Copy controls, a divider-free header, rounded shell and source-only copying. Unknown language labels preserve their authored case. Wrap remains independent per code block and survives source growth and closure. Actively streaming open fences withhold Copy; Copy becomes available on closure or when the response stops, including an unterminated final fence. Incomplete source stays readable. Clipboard failures remain retryable, success resets after two seconds, and an unresolved copy keeps its button pending across source changes rather than exposing an inert control.

The renderer uses the pinned set of 45 Highlight.js grammars through Lowlight plus eight directly imported grammars, including the Wolfram alias and detection when no language is supplied. Highlight.js 11.11.2 is now an explicit exact dependency, matching the previously resolved transitive version; OMP/Bun pins are unchanged. Source renders before enhancement. An IntersectionObserver enables nearby blocks at a 600px margin; per-block starts are limited to once per 120ms. Current source is never replaced by an obsolete highlighted result; a compatible highlighted prefix can remain while plain text appends. Selection offsets survive same-text syntax span replacement as well as streamed text changes.

The light/dark Highlight.js palette and selector groups now follow the extracted stylesheet, including italic comments and distinct literal, variable, attribute and name colors. Existing syntax overrides remain supported; attribute/name/error colors join the validated theme-file/settings token inventory. The code font remains configurable; dedicated transcript line-height and radius tokens preserve the native default 1.5/20px values, with a 20px line-height floor. Ordinary code has no invented Run, Save, Download, Expand or line-number toolbar. SVG and Mermaid previews are separate required surfaces, not implemented by this ordinary code component.

Selections spanning prose and code within one Markdown block now copy structural plain text and sanitized rich HTML without toolbar or hidden labels; selections wholly inside code preserve exact selected whitespace. Table copying shares the sanitizer. Cross-message selections and full footnote/math normalization remain separate.

Validation: 58 focused regressions / 338 assertions, project and acceptance-fixture typechecks, and the production build pass. Seven hidden-Electron component checks passed with three PNG/Chromium AX captures at 460×700 and 1440×1000, DPR 2; production hashes stayed stable. Clipboard APIs and ClipboardEvent data are controlled at the fixture boundary, without touching the OS clipboard. The final unit-fixture-only correction is recorded separately from the captured source hashes.

This checkpoint does not establish installed Work or native-pixel parity. The frozen main/side/light conversation captures show the ordinary toolbar; Copy success/failure, wrap-on and streaming transitions lack matching captures. Their AX wrap control is a checkbox while the pinned source uses aria-pressed button semantics; that difference is explicit. Lazy loading the grammar chunk, sticky/preview caller variants and full transcript selection semantics outside the exercised code paths remain open. The synchronous 100,000-character highlighting cap remains an implementation limitation; larger source stays visible and copyable. Private reference and acceptance evidence is under `.data/transcript-code-blocks-2026-09-07/`.

## Transcript table controls — 2026-09-07

Conversation tables now expose the pinned Copy table and Expand table controls. Copy writes the individual table's trimmed original Markdown plus sanitized rich HTML, preserving escaped pipes, formatting and Unicode; it never substitutes tab-separated or CSV text. ClipboardItem support selects multi-format output, with plain Markdown fallback only when the API is absent. Failed writes remain visible and retryable instead of showing the pinned implementation's optimistic Copied state. Successful copy resets after two seconds.

The generic Markdown renderer defaults to no wide blocks. Ordinary user/assistant conversation text opts in, matching the traced local-conversation caller. Expand opens a full-viewport modal with a scrollable table, close/Escape focus restoration and live content updates. Preview has no download or zoom controls. Table actions, cell rules, modal geometry and Copy/Expand SVGs follow the extracted source; native hover and whole-window pixel equivalence remain unverified.

Clipboard HTML retains useful table/inline structure but excludes controls, executable markup/URLs and temporary image grants. It deliberately omits srcset and flattens unsupported elements to text. This stricter copying boundary is an explicit difference from the pinned DOM copier. Plain Markdown remains the original table source. No CSV/export menu is established by the pinned table source; the older baseline's proposed export gap is not a parity requirement.

Validation: 44 regression tests / 282 assertions, app typecheck/build and fixture-inclusive TypeScript checks pass. Six isolated Electron checks and four PNG/Chromium accessibility captures cover narrow overflow, individual-table clipboard formats, unavailable/rejected clipboard APIs, pending-copy source changes, live expanded content and pointer/Escape focus restoration. Clipboard APIs were controlled; neither the OS clipboard nor an installed Work app was exercised. Private evidence: `.data/transcript-tables-2026-09-07/REPORT.md`. Delayed native tooltips, wide-table edge fades, latest-turn-preview layout and matched native table-state pixels remain open.

## Transcript host-file links — 2026-09-07

Ordinary Markdown links and native transcript file references can now open absolute files outside the current project, including sessions without a cwd. A resolved outside path keeps its host identity and opens the existing standalone Files tab; line/column locations become requests against that exact file's basename. Relative links with a known cwd resolve normally, while relative links without a cwd remain unavailable. The default resolver behavior used by file editors and composer context still enforces its existing workspace boundary; only transcript rendering opts into standalone routing.

Open-options, external application actions and Save as select the same cached WorkspaceState as the file tab. Absolute paths become exact-file targets and basename transport queries; returned option paths are checked before adapting them back to the transcript's path. Existing pending-command/reconnect/location guards remain. Copy path keeps absolute native filename punctuation literal. Opening a cached file tab while disconnected is permitted; repeated location requests reuse the cached buffer without a disconnected-read error. An uncached path remains explicitly unavailable, and reconnect still compares real host revisions without replacing unsaved edits. Network queries, external opening and Save as still require the owning host.

Validation: 92 regression tests / 568 assertions, typecheck/build and an isolated real-host Electron interaction run pass. The latter exercises actual line/column placement, preview/pin, exact literal filenames, controlled Save as, and dirty cached recovery with another offline link click. It uses production components in a fixture context, not full App or installed Work; no native pixel parity is claimed.

The pinned source establishes path/cwd/host dispatch without renderer containment, not the entire opaque backend contract. Folder/file-manager handling, external-editor line navigation, unproven `file:`/`sandbox:` Markdown-link grammar and exact native popup/pixel fidelity remain separate gaps. Media URI handling is not evidence for Markdown-link parsing. Private evidence is under `.data/transcript-host-files-2026-09-07/`; component-host fixtures do not establish installed Work behavior.

## Transcript Markdown images — 2026-09-07

The transcript now resolves Markdown image nodes through a dedicated host-aware loader instead of the former attachment-unavailable placeholder. Absolute POSIX paths, local `file:` URLs and `sandbox:` absolute references use the existing exact-file image grant on the session's host. They do not resolve against the viewing machine or require project membership. Embedded image data is decoded by an `img` element. Remote URLs remain inert; relative paths require a current-file context that ordinary transcript blocks do not supply. Native image content blocks retain their existing attachment transport.

The thumbnail and viewer use the pinned source's ordinary 200-pixel cap, border/radius, loading state, failure fallback and full-window image viewer. The viewer supports scoped gallery navigation, zoom/reset, pointer pan, Escape/focus restoration and local-file Save as through the desktop's existing save path. Leases are released after source replacement, decoding failure, close or unmount; already decoded thumbnails stay mounted through disconnect, and reconnect acquires fresh host grants. Repeated references remain separate gallery positions.

This is a bounded implementation checkpoint, not complete media or pixel parity. Remote-media policy, embedded-data download, pinch/cursor-centred zoom, generated-image context actions, durable offline Markdown image bytes, audio/video and current-file-relative transcript contexts remain open. Host symlink/regular-file restrictions remain in force. The frozen bundle's local SVG capture is a Files-panel preview, not a matching transcript gallery state. Validation and private source/capture details are recorded in `.data/transcript-markdown-images-2026-09-07/REPORT.md`; installed Work and matched native-reference verification remain separate.

## T04/T05 and owner-file links — 2026-09-05, before release 8

[MarkdownText.tsx](../apps/desktop/src/renderer/MarkdownText.tsx) replaces the fence splitter with pinned [react-markdown 10.1.0](https://github.com/remarkjs/react-markdown) and [remark-gfm 4.0.1](https://github.com/remarkjs/remark-gfm). It renders CommonMark/GFM paragraphs, headings, emphasis, inline code, nested lists, read-only task markers, quotes, rules, aligned tables, autolinks and scoped footnotes. Raw HTML stays literal; image syntax shows an explicit placeholder and never loads a remote resource. Ordered native blocks, tool disclosures and actual outcomes remain unchanged.

Fenced/indented code supports tilde and longer delimiters, incomplete streamed fences, missing final newlines, Unicode and CRLF. Code Copy sends the parsed code body without delimiters or the parser's presentation newline; it reports success or a retryable clipboard failure. Wrap changes actual horizontal scrolling and stays associated with the source code position during growth, completion and same-view reconnect. [lowlight 3.3.0](https://github.com/wooorm/lowlight) supplies its 37 registered common grammars and aliases; no language is guessed. Unknown languages and blocks over 100,000 characters are labeled plain text. Registered token classes use the existing Appearance syntax/diff colors. A small [React pre-commit snapshot](https://react.dev/reference/react/Component#getsnapshotbeforeupdate) preserves selections wholly inside a code block when grammar reclassification changes its text spans; it keeps focus in place.

The actual Files panel switches to the requested file and selects the location after the owner read finishes; out-of-range locations report an error. Existing per-file buffers, dirty edits and conflicts are retained. The host independently enforces its realpath boundary. Missing files, escaped symlinks, offline hosts and outside-workspace links remain explicit failures. Browser links use the existing main opener: HTTPS and local HTTP only; embedded credentials, unsupported schemes, protocol-relative URLs and ambiguous locations never become opening actions. Footnote targets and accessibility descriptions are scoped to their message block.

The smallest necessary protocol change is an explicit, backward-compatible display projection: ordered typed content blocks; stable display identity with native entry identity retained; optional tool-call identity/name and actual outcome; optional assistant completion/error/model/usage fields; a distinct representation for supplied native notices and summaries. Preserve native event/turn order. Do not forward the whole native provider object or manufacture a successful outcome when metadata is absent. Old hosts should remain visibly limited.

OMP's pinned native types already distinguish these cases: `@oh-my-pi/pi-ai/src/types.ts` defines `AssistantMessage`, `ToolResultMessage`, `ToolCall`, `ImageContent` and `stopReason`; `@oh-my-pi/pi-coding-agent/src/session/agent-session-events.ts` defines compaction, retry, notices, model/thinking changes and goal updates. The current renderer primarily uses runtime events as invalidations and does not display those event-specific states.
