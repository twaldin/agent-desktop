# Workspace file editor

The Files panel uses the pinned Pierre editor over the existing host-owned workspace service. `WorkspaceState` remains the authority for file content, revisions, dirty buffers, recoverable conflicts and mutation receipts. The renderer does not write through a second editor-specific backend.

## Editing and navigation

Each dedicated file tab is identified by host, workspace and relative path. Opening the same file again activates that tab in its existing dock; different paths and owners remain separate. Transcript links, Review file actions and directory choices use this route. The descriptor survives window-state restoration.

Dedicated files show a compact breadcrumb header and a host-owned recursive file-tree picker above one editor, without the directory browser or nested file-tab strip. Breadcrumb selection opens or reactivates a dock tab; it cannot change another tab’s file identity. The generic Files directory view remains available for navigation and legacy restoration.

Each open text file has a stable editor instance while its panel remains mounted. Switching files or temporarily viewing Changes preserves its undo history and selection. Hiding a dock keeps the editor mounted but inactive. Closing or moving a tab between dock regions remounts the editor; cached text survives, but native undo history and selection are not yet durable across those remounts. A line request waits for the owning file read and visible editor, then selects the requested one-based line or places the caret at its one-based UTF-16 column. Invalid locations show an error against the current buffer, including unsaved edits. LF, CRLF and CR line boundaries are supported.

Keyboard editing and find come from Pierre. UI edits autosave after three seconds of idle; Command/Control-S can save immediately through the same receipt path. The editor remains writable offline and during an in-flight save; the save callback respects connection, restoration and pending-command gates. Editor controls own their keyboard events before app shortcuts.

Command-L on macOS, or Control-L elsewhere, opens Go to line from the active file panel. The control closes Find and previews a centered line without taking focus from its input. Positive whole numbers clamp to the file range; negative numbers count from the end. Zero, unsafe integers and column/percentage syntax are invalid. Enter commits the line-start cursor and returns focus to the editor. Escape or Close restores the opening selection and scroll snapshot; clicking away retains the preview. Reopening starts with empty input, while repeating the shortcut in an open control selects its current value. Navigation changes neither file text nor host state. The current editor uses Pierre's unvirtualized `File`; this does not establish large-file performance.

Syntax highlighting uses the existing pinned review theme data. Editor background, code font family, size, weight and line height use the app's theme tokens. No additional dependency or runtime version was introduced.

## File preservation

- A save persists its original command ID before dispatch and includes the baseline revision. A lost receipt retains that ID for explicit recovery.
- Edits made after submission remain dirty when the saved revision is acknowledged.
- Each file has an in-memory generation. A read response from before a later edit, resolution or save receipt cannot replace that newer state or introduce a stale conflict.
- Offline text is cached under the host and workspace identity. Opted-in autosave drafts resume on reconnect with the original baseline revision; CAS or a host read preserves divergent local and host revisions as a conflict. Legacy manual buffers do not gain automatic save intent on upgrade.
- Choosing the host version retains the previous local text for recovery. Keeping local edits adopts the inspected host revision for the next save; opted-in autosave resumes after the normal debounce.
- Binary, oversized and unsupported-encoding files retain their existing non-editable states. UTF-8 BOM preservation belongs to the host write contract.

## Save as on the viewing desktop

Save as… appears after Open in folder. The desktop opens its native save dialog with the source basename, sanitized like the reference. Cancellation returns without resolving the host or reading its file. After selection, main resolves the explicitly selected host once and uses authenticated, owner-fenced queries to copy raw bytes from the catalogued project/session. The destination comes only from the native dialog; renderer code supplies neither a destination nor file contents.

The copied data is the current host file, not an unsaved editor buffer. Save as does not force autosave, rename the editor tab, consume its draft, create a session, or change workspace ownership. It supports empty files, binary data and files above the editor’s text size limit. One MiB chunks bind to a revision derived from file identity and nanosecond metadata; the host rechecks its file descriptor, confined path and root for each read. The client rejects mismatched owner, path, revision, offset, size and invalid/truncated Base64, then rechecks source metadata before publishing the copy. A same-file shortcut applies only to the confirmed local host; equal remote and local path strings do not establish identity.

The selected destination is written through a temporary file in its actual parent. Normal transfer/read failures preserve an existing destination and remove temporary data. Source or destination changes observed during transfer abort the copy. New filenames publish without overwriting a concurrently created file. Existing and dangling destination symlinks retain the link and write its referent. Existing regular destination mode is retained; new files follow the process umask. Replacement changes the destination inode; extended attributes, ACLs and hard-link relationships are not preserved by this implementation.

Existing-file replacement is an ordinary rename after metadata checks, not an atomic cross-process compare-and-swap. A narrow check-to-rename race with other applications remains, as do ordinary filesystem parent/symlink races. Metadata revisions are not immutable content snapshots. Process death can leave a temporary file, and the copy has no durable restart receipt. These limits are not claims of exact native behavior: the pinned app streams directly into the destination; staging and change checks are deliberate protection against a truncated destination after remote failure.

The menu disables Save as offline or when the desktop bridge is unavailable. Duplicate operations in one viewing window are rejected by main; closing that window aborts transfer. Errors retain the editor state and show an actionable explanation. The destination dialog owns overwrite confirmation; its actual OS interaction and installed preload/main path still need native acceptance.

## Skill source/preview save guard

The skill editor now uses the same save-before-switch contract as ordinary Markdown files. A requested switch waits for the current write and any newer edits to reach the owning host. Rapid requests are coalesced by disabling the pending toggle. Dirty offline buffers, conflicts, failed recovery storage and unconfirmed receipts leave the current view and text intact. Inspect file can confirm an unknown save through a read; switching never silently replays that write. Leaving the active panel or replacing its controller aborts the delayed mode change. An already-delivered write can finish, while the canceled switch does not drain later edits.
