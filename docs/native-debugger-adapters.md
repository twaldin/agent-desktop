# Native debugger adapter configuration

Configuration → Debugger adapters reads the selected host profile and project through its existing discovery worker. It lists native built-ins, configured adapters, unavailable commands, source priority and effective field provenance. Viewing or saving does not create a session or launch an adapter. Command availability is the pinned native resolver's current result, not proof that a debugger can launch successfully.

The editor changes an original admitted local source by opaque identity. It supports command, ordered arguments, languages, file types, root markers, directory-program support, connection mode, and native launch/attach defaults. Arbitrary JSON belongs only in those defaults objects. Unknown saved fields and unrelated document values survive structured edits. JSON/YAML formatting and comments can change on serialization. Built-ins, plugin sources, symlinks, malformed documents and unsafe structures are read only; choose an explicit user or project override instead.

Native 18.1.10 merges sources in its own reversed priority order: project root, native project configuration directories, native user directories, plugin roots and home, with JSON/YAML and hidden variants. The display lists highest priority first. Adapter fields merge shallowly except launch and attach defaults, which merge one key deep. Invalid overrides can be ignored by native normalization and are marked separately. Removing an override exposes a lower source or built-in; native DAP has no disabled flag. The editor's current effective values are observations before saving, not previews of removing an override.

Each save checks the original source and an opaque revision covering configuration, discovered roots and native resolution. Conflicts and connection changes retain the draft. Reload displays current saved values; adopting that revision requires an explicit review action. An unknown save outcome never triggers an automatic replay. Drafts stay in renderer memory for their original host/project while the Settings bridge exists; they are not persisted across app restarts.

The native DebugTool resolves configuration for every future launch or attach, including within an existing SDK session. A running debugger keeps its configuration. Plugin-root membership in an already-created native worker still follows that worker's native discovery lifecycle; this settings editor does not refresh or reconfigure a running session.

The read-only native inspector shares source enumeration, normalization, merge and resolution with the original loader. It accepts explicit plugin roots so profile/project reads do not mutate global discovery context. Inspection bounds files to regular files of at most 1 MiB and reports an incomplete inspection when a source cannot be read safely; the original native loader's behavior is unchanged. Symlink content can contribute native effective values, but the host never edits a symlink source.

Controlled acceptance uses a disposable actual SDK AgentSession and its registered DebugTool, a loopback protocol fixture adapter, and production authenticated settings routes with the actual discovery worker. It verifies launch, attach and next-attempt updates without model/provider calls. The fixture adapter does not debug a real program. Production Settings App evidence uses synthetic input, with measured wide/narrow geometry. This is an OMP configuration flow, not a claim of native Codex debugger-screen, installed-debugger, provider or physical-input parity.
