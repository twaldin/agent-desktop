# Sidebar organization

Projects, chats, pinned items and named sections retain their owning host. The sidebar offers By project, By connection and In one list. List mode moves ordinary project chats into Recents; chats in pinned or custom projects stay with those projects. The same model provides numbered-chat targets, independent of disclosure and scrolling.

Project and chat sorting are independently persisted through the existing replicated preferences. The pinned source's Priority order is waiting for a permission/question, unread, active, then idle, with newest activity first within a class. Error and interrupted states alone do not imply a pending question. The read owner supplies unread state from actual session activity and durable read marks. Pinned/custom item positions remain manually ordered.

Fresh organization uses the reference's project grouping and Last updated sorts. Older explicit sidebar records retain connection grouping and manual positions until deliberately changed. The first new sidebar write persists that inferred mode before changing membership, so adding the first section cannot reinterpret the previous layout. Switching to Manual order captures the current displayed order; newly discovered unordered items append after saved positions. Existing explicit moves preserve section and project appearance.

Archive all chats captures the section's current host/chat targets and asks for confirmation. It uses the existing session archive command on each owner. It does not delete projects, session history or files, and does not stop a running agent. Successful chats leave the active list; refused or offline targets remain available for deliberate retry. Cancel before confirmation sends no commands. Archived chats can be reopened with their original IDs.

Section/project collapse and the selected route remain window-local and use the existing window store. Shared membership, ordering and appearance use host-backed preference receipts. The current window does not overwrite another window's disclosure state.

The navigation glyphs reproduce the initial vector frame of the pinned 7982 New chat, Plugins and Search assets. Default project folders switch between the pinned closed and expanded vectors; custom markers retain their chosen presentation. Unread activity uses the trailing status rail and an accessible Unread label. Hover animation, full reference pixels, full App composition and cross-machine physical acceptance require separate evidence. Helper screenshots are build7868 and are contextual rather than proof of matching 7982 behavior.

The acceptance fixture mounts the production sidebar and preference/read owners in Electron with an isolated profile. Two disposable real host services handle authenticated preference and archive requests; a temporary window store acknowledges and reopens disclosure/navigation state. Controlled native-event-shaped inputs through the actual HostStore event and NotificationEvents owners and a deliberate host refusal exercise unread and error behavior without personal providers, external sign-in or live Codex UI. Fixture controls are not product controls. Supplied checkpoints distinguish this mounted surface from full installed-App and provider acceptance.

## Explore and navigation customization

New chat remains the primary action. Available default destinations appear in Pull requests, Scheduled, Plugins order. Explore offers Archive and destinations hidden from direct navigation. A selected hidden destination is temporarily shown with a Pin to sidebar action; pinning makes it persistent. New chat exits Archive and Activity.

Explore → Customize and the navigation context menu open inline customization. Visibility controls toggle direct navigation. Reorder handles support pointer dragging or Space/Enter to pick up, arrow keys to move, Space/Enter to drop, and Escape to cancel. Focus stays with the handle during save and cancellation. Done returns focus to Explore. Reset restores available destinations' defaults without erasing unavailable entries; Explore remains reachable when all destinations are hidden.

`sidebar.navigation` is a versioned, atomic value in the existing host-backed preference map. The viewing machine's local host owns writes, independently of the selected workspace host. Its capability advertisement gates editing. The navigation owner reuses the shared v2 reader, revision comparison and command receipt loop, with owner-scoped caches and durable unsaved intent. A failed or uncertain write remains recoverable after reopen; Retry is reachable even after a refresh clears its transient error. Uncertain retry uses the original command ID. Availability only changes the rendered projection, not saved visibility or order.

The header's Activity control lists native chats that are unread, running or waiting for a permission/question, and navigates to their original host/session. There is no fabricated ChatGPT/Work mode selector: OMP currently has no alternative product-mode route. Project markers remain visible on pointer hover; project actions appear on hover, keyboard focus, or an open project menu rather than ordinary retained pointer focus.

The production-App acceptance entrypoint is `bun scripts/acceptance/sidebar-explore-app/run.ts <fresh-private-output-directory>`. It runs the actual App with an isolated real host, authenticated transports, durable preference/window stores and no provider prompts. It exercises navigation, menu and keyboard use, persistence across actual window reopen, capability loss/recovery, rejected and uncertain writes, original-command retry, all-hidden recovery and reset. Its renderer captures and received-key records are not native-window or pixel-parity proof. Saved 7868 captures qualify structure only; the native backdrop, display and key-window baseline must be matched separately before claiming 7982 pixel parity.
