# Native settings and model controls

This service targets OMP 18.1.10 release `f241301c83726afe75a847e919b89977a54dafbe`. `settingsCatalog()` reads the actual installed `SETTINGS_SCHEMA` and asserts 484 entries. Every entry has a typed recursive schema, owning-host scope, native group/tab, application timing, credential flag and source identity. Entries lacking native UI metadata remain listed with generated labels. Unknown compound schemas reject; they never become silently accepted JSON.

`OmpSettings.open({agentDir?,cwd})` returns `catalog()`, `read()`, `options(path)`, `mutate({expectedRevision,scope,path,operation,value?})` and `dispose()`. `scope` is global or project; operation is set or reset. Reset assigns the exact native default at that scope. It does **not** remove an override or mean inherit. Only global scope is supported for native auth configuration and setupVersion. Reads preserve native global/project/effective layers, including read-only native process overlays. Mutations affect new sessions; native terminal settings configure the terminal UI, not desktop appearance.

Native `Settings.loadReadOnly` supplies merged reads. Global mutations use native `Settings.loadIsolated`, `set` and `flush`. General project mutations are an adapter over the native exported YAML serialization, file lock and atomic replacement helpers; the SDK has no general project setter. Writes target `.omp/config.yml`, preserve valid symlinks, reject dangling links, and compare the requested value with the persisted result. Native merging rules and comments/formatting behavior remain native. A project setting shadowed by a process overlay is explicitly reported through the effective origin. No native global auth/profile preferences are replicated into desktop preferences.

Revisions are opaque random IDs for immutable source/effective snapshots. Private fingerprints include credential-dependent state but are never returned. Global and project locks check revisions and persistence before acknowledging writes. Two desktop clients cannot overwrite the same stale revision successfully. An idle HTTP service may be evicted from its bounded cache; its old revision then requires reload. Credential descriptors return configured flags only, never values/defaults/layer contents. API keys, login codes and setting bodies bypass durable host command/event journals.

`WorkerSession.getControls()` returns native model/thinking/service tiers, all setting states and the exact supported runtime override paths. `mutateControls` compares revisions and delegates to native model/thinking/service-tier setters or `Settings.override/clearOverride`. Model, thinking and service tiers persist in native session history. Runtime overrides expire with that session worker and are not written to its global/project files. Auth, terminal and constructor-only settings require native config and a new session. The host serializes mutations with prompt admission; extension answer paths remain independent to avoid deadlock.

`WorkerRuntime.listModels(cwd,{refresh:true})` and `listModelCapabilities` rebuild the discovery context with new native settings/auth/model registries. Read-only native settings cannot reload themselves. Native settings and models file caches are invalidated before replacement; old resources close after queued readers finish. `authenticated` is native resolvable credential metadata; `available` is actual native getAvailable membership; `disabledInSettings` is the native provider-disable flag. The catalog remains complete. A disabled provider cannot be explicitly selected in its native session. Existing session settings retain their native snapshot until explicitly overridden or reopened.

`modelCapabilities` projects public capabilities, all native thinking fields, family-specific tier selectors, costs and allowlisted primitive compat flags. Sensitive URL/header/body/metadata fields are withheld. Native input-schema compatibility structures, routing, whenThinking and model identity are projected; remaining undeclared capability fields appear by name in `unmappedCapabilityFields`. `model-control-coverage.json` accounts for the pinned model and stream-option fields and distinguishes native runtime plumbing, implemented configuration and outstanding editors. It is evidence of remaining scope, not full parity acceptance.

`SettingsHttp` routes (after parent authentication):

- GET `/v1/settings/catalog`
- POST `/v1/settings/read` with `{target?}`
- POST `/v1/settings/mutate` with `{target?,mutation}`
- POST `/v1/settings/options` with `{target?,path}`
- POST `/v1/models/capabilities` with `{target?,refresh?}`
- GET/POST `/v1/sessions/:id/controls` (POST is the direct control mutation)

Targets contain catalog project/session IDs only. Raw cwd paths are rejected. All responses use no-store, requests are bounded to 1 MiB and 32 JSON nesting levels, and unknown fields are rejected. The cache defaults to 32 services with active leases; when all are busy another target receives 503. Mutations publish only target/scope invalidation. Parent authentication, admission serialization and transport bridge belong to server integration.

The renderer's `NativeSettings` exposes all 484 core entries through tabs/groups, search and advanced sections. It uses recursive typed fields for compound maps/arrays/objects/unions, keeps secrets write-only and preserves local edits on failed/conflicting writes. Reload never silently rebases an existing edit; the user reviews the saved value and explicitly uses the new revision. Native theme registry choices and composer builtins can be loaded where applicable. Extension composer shapes, extension-defined settings and custom TUI factories remain explicit integration gaps. Model/provider definitions and compatibility fields declared by the pinned native input schema now have dedicated typed editors. Native extension/custom commands now receive a distinct host handled-command receipt after actual handler completion and session persistence; builtin command dispatch remains a separate integration gap. See `../omp/README.md`.

Validation includes real temporary native global/project writes, reloads, invalid-value/no-change checks, concurrent revision conflicts, secret redaction, valid symlink preservation, actual worker controls/resume and discovery refresh after global/project/models.yml changes. Renderer contracts exercise all 484 descriptors, compound fields, late reads, conflicts and write-only rendering. These contracts use temporary stores/labelled fixtures and no provider calls; they do not constitute live OAuth, multi-device or visual parity acceptance.


## Editable native model definitions

GET `/v1/models/definitions` returns `{catalog,snapshot}`; POST the same path accepts `{expectedRevision,changes}` and returns the saved snapshot. `DesktopBridge.getModelDefinitions(hostId?)` and `setModelDefinitions(mutation,hostId?)` use these routes. This configuration belongs only to the owning host's native model file; no project target or arbitrary path is accepted. Every change is a typed `set` or `remove` operation on a declared path under `providers`.

`OmpModelDefinitionsStore` derives its recursive catalog from the exact native `getModelsConfigSchema().toJsonSchema({io:"input"})`. Conversion is lazy, so a future unsupported descriptor rejects its catalog instead of preventing host startup. Final documents run the real native schema, including narrow/normalization callbacks, followed by native `validateProviderConfiguration`. Required endpoints/APIs/auth, positive model limits, discovery constraints and thinking vocabulary therefore use OMP's actual rules. Legacy thinking syntax is retained on disk and normalized by the native registry when read. Existing undeclared fields stay on disk, with only their paths returned; new undeclared fields are rejected.

The UI edits providers, custom model identities/limits/costs/thinking, bundled-model overrides, nested compat/whenThinking, routing lists, discovery and native request fields. Optional fields have Set/Remove controls, arrays have ordered controls, maps have named entries, and unconstrained native request bodies use recursive typed JSON values. A raw JSON textarea is not the editor. Saved credentials, headers, endpoints, arbitrary request metadata and extra bodies are concealed; new entries are write-only. Ordinary compound writes retain concealed values. Explicit clear operations run before replacement values. Model edits submit exact array-index patches anchored to the read revision, preserving each row's own concealed values even with duplicate IDs. Unique IDs permit reordering by native model identity. Duplicate IDs disable reordering and reject direct whole-array replacements; an enclosing provider edit may retain only an unchanged public model array by index. Give rows distinct IDs through exact-row edits before reordering.

Concurrent stores compare opaque revisions inside the native file lock and again before publishing the staged replacement. Existing valid symlink targets, file modes and ownership are preserved. The staged file and parent directory are synced around native atomic replacement. A write error after publication remains an error and asks the client to reload rather than retry blindly. YAML fallback stays at models.yaml. Legacy models.json is read without migration; an explicit write creates models.yml and preserves the legacy file and its mode/owner. Files over 4 MiB and mutation requests over 1 MiB are rejected with explicit errors.

Model edits preserve local input on conflict. Rebase locates an existing edited model by its original unique native id after another client reorders the array; a removed original model is not recreated silently at another index. If that ID was duplicated in the original or refreshed snapshot, automatic rebase rejects and preserves the local edit until the user discards it and selects the exact current row. Saved definitions trigger credential-free global invalidation; refreshed discovery and new sessions see native changes. Existing workers keep their loaded definitions until reopened. Packaged visual and provider-specific live acceptance remain separate from these temporary native-store/registry and renderer contracts.
