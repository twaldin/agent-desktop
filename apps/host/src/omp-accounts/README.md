# Native accounts backend

`OmpAccounts.open({agentDir?, cwd?, selectionBridge?})` loads the exact OMP 18.1.10 native provider/auth implementation. It honors each host's environment/config/native broker and account-pool behavior. It does not run a new account broker or implement credential ranking/rotation. The module never calls reset-credit APIs.

The public API is `listProviders`, `listAccounts(providerId)`, write-only `setApiKey(providerId,key)`, `removeCredential(providerId,credentialId)`, `startLogin(providerId)`, `pendingLogin(loginId)`, `respond(loginId,requestId,response)`, `cancelLogin`, `subscribe`, and `dispose`. `startLogin` returns `{loginId,completion}`; its completion is a terminal `LoginSnapshot`, not an unverified boolean success. API-key writes report storage, not a successful provider authentication probe. Changes emit `accounts.changed` so the owning host can refresh affected model/account views.

Provider coverage combines every `PROVIDER_REGISTRY` definition (including hidden/login-only/service providers), registered runtime OAuth providers, configured/model/discovery providers, and stored/disabled-only providers. Disabled custom providers with zero models retain their canonical config names. Returned provider fields explain native login visibility, availability, aliases such as `openai-codex-device -> openai-codex`, callback port, paste-code flow, stored key/account counts, native auth origin and configured state. Command-backed keys are identified by presence without running their key commands for display. Configured/auth-origin flags are not provider validation.

All returns use allowlists. Credential IDs, identity/org/project fields and disabled status are exposed; API keys, access/refresh tokens, provider request headers, serialized credentials, raw disable causes and native error bodies are excluded. Submitted login responses are write-only and never stored in snapshots/events. The broker origin excludes URL userinfo/path/query; bearer tokens remain private. Native authorization URLs, device codes/instructions and progress callbacks are intentional login UI artifacts while a login is pending, then authorization URLs are cleared.

API-key writes use native upsert behavior with the same `source:login` precedence as native key login. Local writes use `AuthStorage.upsertCredential`; broker writes use native `AuthBrokerClient.uploadCredential` followed by native snapshot revalidation. This preserves canonical broker refresh credentials. The module never feeds redacted OAuth snapshot rows to replace-all storage, and never copies a credential snapshot into app state. It preserves the native rule that stored OAuth can outrank a stored API key.

The callback bridge supports all four native controller surfaces: `onAuth`, `onProgress`, `onPrompt` (including input before a URL and `allowEmpty`), and abortable `onManualCodeInput`. Pending prompts have unique one-use IDs; stale/duplicate responses fail. Cancellation is passed to native callbacks. A real returned storage identity takes precedence if cancellation raced a completed native write. A native error is not proof that no remote write occurred; do not automatically retry an uncertain credential mutation.

The SDK supplies no typed username/password/select/multi-field descriptor for `onPrompt`. Every response is therefore a sensitive single-text field, preserving the native message/placeholder and empty-input rule. Renderer controls must support reveal/paste appropriately. Providers that encode choices in prompt text remain text prompts; do not invent a structured native form. Custom provider code using terminal input outside these callbacks cannot be bridged through this contract.

Callback HTTP listeners run on the owning host, with native ports unchanged. A loopback `launchUrl` is only meaningful on that host; remote clients should expose the full authorization URL and manual redirect/code input where the native flow supports it. This module does not register an OS URL scheme or tunnel fixed localhost callbacks. Callback/native-scheme behavior still requires real sign-in verification.

Account preference is session-local. `listSessionAccounts` and `pinSessionAccount` require the injected `AccountSelectionBridge`; they fail explicitly when disconnected. `createNativeAccountSelectionBridge(resolveNativeSession)` is provided for the owning worker: it calls the native session account list/pin APIs, rejects busy sessions, and persists the selection with native `recordCredentialPin` plus `flush`. OMP's normal usage/account retry rules may still route around that preference. There is no fabricated global selected account, manual rotation algorithm or forced disabled-account activation.

Extension provider functions are registered in their owning process. This backend exposes runtime providers registered in its own process and declares `extensionProviderCoverage:registered-in-this-process-only`; workers' extension-defined registries/login functions require a worker bridge. Constructing the account catalog alone does not silently load user extensions or complete that integration.

Tests use pure callback contracts plus native SQLite stores and an actual loopback OMP auth broker in an isolated child environment. Fixture provider callbacks supply labeled test credentials; outbound provider fetch is blocked. They verify complete built-in provider coverage, write-only data, stable credential IDs, preserved OAuth rows/refresh values during broker key upserts, one-use prompts, cancellation and truthful no-credential outcomes. They are not live provider sign-in/account-switch acceptance evidence.
