# Native session workers

`WorkerRuntime` owns one Bun child process per OMP session and one separate reusable process for model discovery. The daemon imports SDK types only; each child initializes the real `OmpRuntime`. Closing a desktop connection does not touch these children. Call runtime/session `dispose` only when the owning service intends to stop them.

The interface matches the SDK adapter except `getMessages()` returns a promise. Metadata getters use child snapshots, whose revisions prevent delayed events from reverting newer state. `startPrompt()` preserves independent native `accepted` and `completion` promises across IPC; a dead child rejects pending calls with `WorkerFailureError` and never invents a successful receipt or model response.

`getControls()`/`mutateControls()` delegate revisioned native session controls to the owning worker. `listModelCapabilities(cwd,{refresh?})` uses the discovery process and strict capability projection. A refresh replaces cached read-only settings/model/auth context; native global/project/model file edits and provider disablement become visible. See `../omp-settings/README.md` for scopes, persistence, secret protection and remaining model-definition/extension UI coverage.

Each handle also exposes async `listAccountChoices`, `pinAccount`, `releaseAccountForReselection`, `listInteractions`, `respondInteraction` and `cancelInteractions`, delegated to its owning native session. Pass `interactions:true` to create/open only when the daemon exposes an actual UI. Bridge events share the existing acknowledged native-event channel. The session is returned before native extension startup, which runs on its first prompt admission; startup callbacks cannot deadlock create/open. Polling `listInteractions` and event delivery are independent IPC paths: a snapshot may arrive before its buffered notification. Ordinary desktop listener removal/disconnection leaves all pending questions alive.

Use `new WorkerRuntime({ onWorkerFailure })` to record failures. The callback receives `{type:"worker_failure", message, pid, sessionId?, exitCode?, signalCode?}`. Each handle also exposes `workerPid`, `workerFailure` and `subscribeWorkerFailure`. A worker failure does not dispose another worker. Native history remains on its owning filesystem. Recovery is explicit: dispose the failed handle, establish ownership, and open its original file. Commands with uncertain outcomes must not be automatically replayed.

The children communicate over Bun's private subprocess IPC, separately from stdout/stderr. Protocol 7 adds owner-bound current-viewport reads for exact native browser targets. The request must match the current worker PID, tab name, and target ID; the worker returns only a bounded JPEG with dimensions checked from its header. Capture does not activate, navigate, resize, or close the tab, and cmux capture remains unsupported. Protocol 6 and earlier workers are rejected before initialization and reaped. The exact disposal acknowledgement remains required. Native event delivery uses acknowledgements with a 32 MiB/2048-event backlog limit. Exceeding it fails that worker visibly rather than silently dropping native events. At most 128 request phases are pending per child. Raw credentials are never part of this protocol; model metadata uses the existing adapter allowlist. Native terminal output is not used as a protocol or relayed to clients. Operation errors and fatal process errors are reported through IPC; abrupt exits report their code/signal.

`startPrompt(text,{images})` accepts private `{attachment:ImageAttachmentRef,data:Uint8Array}` snapshots from the owning image store. The parent and worker validate/capture ordered metadata, byte count and SHA-256; decoding/container/pixel validation belongs to that store. Limits are four images and 20 MiB total. Image-only text is supported. The actual selected native model must accept images and `images.blockImages` must be false; attachment-bearing slash commands and steering fail before their handlers. `images:[]` preserves ordinary text behavior. Busy image submissions are rejected before another large IPC copy.

`NativeImagePrompt` verifies each slot using pinned native normalization on the original images, then passes the originals to the SDK. It observes the owned public `agent.prompt` instance before dispatch, rechecks model/settings, verifies normalized order/count/hash and rejects native persistence-identity collisions. Only that exact user object can earn an append/flush receipt. No timestamps or native history fields are invented. The observer restores on completion/failure. Normalization is deliberately run twice on the originals for verification; it is not run twice on lossy normalized output. A nondeterministic or extension-mutated result rejects visibly. Receipts include ordered attachment IDs, original hashes and actual recorded hashes. An error after attributable dispatch that prevents certification, or loss of the acceptance transport after an image send attempt, has `code:"OUTCOME_UNKNOWN"`; retain the original host command identity and draft. Explicit native preflight rejection remains definite. The worker does not implement a second command ledger.

Worker event projection occurs before cloning or queue accounting. `WorkerEvent` retains native event types, bounded error/identity/thinking/lifecycle metadata and the explicit interaction bridge; raw message bodies, images and provider payloads remain native. The transcript mirror projects pending images before retaining display copies. Structured image blocks include `nativeType:"image"` for older renderers plus block index, MIME and available hash/size. `getImage(nativeEntryId,blockIndex)` looks only in the owning manager's native entry map and returns actual recorded bytes; arbitrary paths/URLs are never inputs. Native SDK reopening may already materialize its blob references; this API makes transfer lazy, not SDK loading. Retrieval is capped at 20 MiB and two concurrent reads per session. Unresolved blobs, unsupported native image formats and invalid identities fail explicitly.

`images.test.ts` uses real Bun workers, the owner image store, the native manager/agent/normalizer/blob format, and a labelled controlled provider. It verifies image-only order, transformed hashes, blob externalization/reopen, lazy retrieval, mutation/unsupported guards, an explicit flush-certification fault, abort, and an exact four-image 20 MiB batch. Event tests verify projection never reads image/provider bodies and preserve native errors/thinking. These are source contracts; real provider vision, HTTP/renderer activation, installed UI and physical-device attachment acceptance remain separate work.

Native environment/authentication is inherited unchanged by default. An explicit `agentDir` becomes a child-only `PI_CODING_AGENT_DIR` before importing OMP, aligning global native directories, settings and session defaults. Tests use an isolated environment and temporary home/agent/project directories. Production session paths are not replaced with a new worker-specific layout.

Installed services should pass absolute `executablePath` and bundled `workerPath`. Source runs default to the current Bun executable and adjacent `entry.ts`. The host must package the worker entry and its actual dependencies. This is process failure isolation, not an OS tool sandbox. External import ownership and host restart/draft/command recovery remain separate responsibilities.

On IPC disconnection the child disposes OMP and exits, with a deadline; it cannot retain ownership indefinitely after its daemon dies. Shutdown requests drain native disposal, then exit. The parent kills an unresponsive child at its shutdown deadline. Ordinary renderer closure leaves daemon IPC connected and execution running.

`bun test apps/host/src/omp-workers/runtime.test.ts` starts real Bun workers and real native OMP sessions, exercises title-slot-aware original-ID resume, kills one temporary worker with SIGKILL while another remains usable, and checks preflight rejection/startup recovery. It also writes labelled fixture accounts through another native process, checks discovery/prompt credential refresh, independent pins and pin resume, drives select/confirm/input/editor through a configured native fixture extension, and aborts an actual session_start question before input dispatch. A separate temporary native SDK process runs the actual write tool's permission gate: denied writes leave no file, explicit approval produces the exact requested file. Outbound provider fetch is rejected; fixture account values/extension commands are labelled contracts and no model responses are mocked. These tests complement separate live provider/device evidence; they do not replace it.
