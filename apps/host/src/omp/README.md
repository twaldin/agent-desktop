# OMP 18.1.10 adapter

This Bun-only module uses the installed `@oh-my-pi/pi-coding-agent@18.1.10` SDK. It does not call the installed CLI or emulate a provider. The exact upstream release is `f241301c83726afe75a847e919b89977a54dafbe`; canonical coverage evidence is in `.reference/omp-18.1.10-release/`.

The host owns one `OmpRuntime` and its handles. Each native session has independent settings, auth storage, model registry and agent registry. Closing a renderer must not dispose the runtime. The owning service must establish file ownership before `open`: OMP has no cross-process session lock. This adapter rejects a second open within its own runtime, missing files and unavailable recorded working directories. It preserves native session identity, file and cwd, and calls `ensureOnDisk` before returning a new handle.

`listModels(cwd)` loads native local/broker authentication and cached native model metadata. `{refresh:true}` replaces its discovery context with newly read native settings, auth and model registries; read-only native Settings cannot reload themselves. Native file caches are invalidated, broker credentials revalidated, and online-if-uncached model discovery requested before replacing the old context. Discovery reads/refreshes for one cwd are queued so no old auth store closes during a reader. New prompt admissions and explicit model/account changes also revalidate credentials. `authenticated` is resolvable credential metadata; `available` is native getAvailable membership; `disabledInSettings` preserves the native provider-disable flag. These are not successful credential probes. Returned model metadata uses an allowlist because native model headers can contain credentials. Nullable limits remain nullable. `listModelCapabilities` adds native auto/off/effort selectors, costs, public compat and explicit names of unmapped fields.

Use `startPrompt(text, options)` for submission. Await `accepted` before consuming the captured draft revision. `{kind:"user-message",entryId}` identifies an actual flushed native user entry. `{kind:"native-command",command}` means a known native extension/custom command handler consumed the input and its pending native session writes passed `flush`. It does not invent a user message or claim that a cancelled confirmation approved an action. `null` is unaccepted input; preflight, command and storage errors reject. Observe `completion` independently for the native turn result. The native `prompt()` boolean alone cannot establish acceptance: false also covers dropped/aborted preflight, and the SDK catches command errors before returning false. One admission is allowed at a time, and steering is rejected until admission settles. Storage failure may follow real side effects; preserve uncertainty and never automatically reissue the request.

`commands.ts` uses pinned native registered handlers, command contexts, extension `runScoped`, argument parser and markdown/template expansion. This exposes actual return/throw once without replacing native callbacks or modifying OMP. Extension errors still emit the native error notice; they also reject admission rather than becoming success. A custom string is forwarded through the real native prompt pipeline and needs a real persisted user entry. Abort before dispatch rejects admission. Cancelling a native dialog can let its handler return normally; that is handled input, not successful execution of the declined side effect. Command admission checks active compaction/abort explicitly because the SDK's private manual-compaction cleanup promise is not exposed for direct handler dispatch.

Native builtin slash commands are a separate dispatcher and are not newly enabled by this fix. Known unconnected builtins fail explicitly; extension/custom names retain their native SDK precedence. `/move`, session replacement and other host-owned identity transitions require their own catalog/ownership integration. Unknown slash text still follows the ordinary native prompt path. The host persists the exact admission receipt in its command result, clears only the submitted draft revision, retains error drafts, reconciles real native title changes, and does not use a local command string as an automatic conversation title. Same-ID retries return the stored result through restart, including failure results with partial side effects; interrupted pending outcomes remain unknown and are not replayed.

`getMessages()` projects OMP's full display transcript and mirrors actual in-flight assistant/tool events. Native durable message entry IDs are retained; derived display/stream records use separately marked IDs. The mirror never fabricates model/tool responses. Complete raw native events are also forwarded so richer views can consume their metadata. Account credentials and native model objects are never serialized by this adapter.

Current boundary limitations remain explicit:

- `interactions:true` on create/open installs the real `ExtensionUIContext` for tools and enables native interactive tools. Omit it until the daemon and renderer actually expose the bridge. Native extension initialization/session_start is deferred to first `startPrompt`, after the handle exists. Startup questions are answerable through that handle, and abort prevents the submitted input from dispatching afterward. Startup extension messages are outside the submitted draft's admission receipt. Native usage-reserve confirmations use the same real confirmation bridge; configured native automatic policies are not replaced. The adapter never enables `autoApprove` and does not provide an OS sandbox.
- Settings load through `Settings.loadReadOnly`, preserving effective native configuration without config/marker migrations. Model/thinking selections write session state, not global defaults. Native settings editing needs a separate explicit mutation path.
- Native auth refreshes and model discovery/cache writes follow OMP behavior. Multiple SDK sessions in one process still share some upstream global subsystems; independent process failure isolation requires the owning service's worker boundary.
- Native file `flush` provides visibility through the OS page cache, not an fsync power-loss guarantee. Streaming partials are in memory until OMP emits/persists completed messages; abrupt worker death can lose partial output.
- External import ownership, distributed command/draft persistence, raw event transport, interactive callback resolution and provider error/status presentation belong to the host and shared protocol.

## Session account selection

`listAccountChoices()` returns the current model provider and safe OAuth account metadata from this exact native session's AuthStorage/session ID. `pinAccount(credentialId)` invokes native selection, records OMP's own hashed credential-pin entry, and flushes it so resume can restore the selected account even before another turn. Explicit switching is another pin. `releaseAccountForReselection()` releases the live sticky account for native selection on the next request. This is not a permanent automatic-routing mode: native history still records the last account and may restore its warm preference on resume. Native routing can always route around an unavailable pinned account. No manual operation invokes error rotation or marks accounts suspect. A running/admitting session rejects account/model mutations.

## Pending native interactions

`listInteractions()` returns pending requests; `respondInteraction(id, response)` accepts only the native option label, a real boolean for confirm, text for input/editor, or `{cancel:true}`. Values are never copied into bridge events. IDs resolve once; invalid/stale responses fail. Advertised selector actions invoke actual native callbacks: left/right settle undefined and emit `navigated`, externalEditor leaves selection pending, timeoutReset rearms the native countdown. Timeouts begin when emitted (`expiresAt`), invoke native timeout callbacks, and return cancellation values rather than approvals. Signals, abort, explicit cancellation and disposal settle waiting callbacks. Closing either desktop must not invoke `cancelInteractions`; daemon IPC disconnection disposes the owner bridge. Keep pending questions until another client/reconnect answers them.

Events and request/response fields are exported from `packages/shared/src/interactions.ts`. Native `AgentSessionEvent` and bridge events share `OmpRuntimeEvent`. The bridge emits `extension_interaction_requested`, `extension_interaction_resolved`, `extension_notification` and `extension_ui_unsupported`. Preserve pending state at the host; an absent renderer is never affirmative consent. Renderer presentation and one-use host command admission are separate integration work.

The supported native UI methods are select, confirm, input, editor and notify. Optional rich `askDialog` is omitted, causing native ask to use its actual sequential selector/editor path. The following surfaces currently throw `UnsupportedOmpUIError` and emit their exact surface name; they remain parity work, not accepted exclusions: custom component factories; raw terminal input; footer/header/editor component factories; widgets (including text widgets); status/working-message/title controls; composer set/paste/get text; autocomplete factories; terminal theme get/list/set operations; and tool-expansion state. No custom factory is run or claimed rendered. Extension newSession/branch/switchSession/shutdown are also explicitly unavailable until the daemon can coordinate native ownership; reload awaits bridge reinitialization support. Native tree navigation, tool/model/thinking/service-tier actions and compaction delegate to OMP.

`bun test apps/host/src/omp` runs projection, interaction callback and native temporary-file admission contracts. These are not live provider or physical-device acceptance. Worker tests separately execute real native permission-gated writes and configured fixture extensions, with provider fetch disabled.

## Native controls

`getControls()` and `mutateControls()` provide revisioned model/thinking/service-tier changes and supported session-only setting overrides. All 484 native setting states are available, with credentials redacted. Model/thinking/tiers persist in native session history; runtime overrides expire when the worker closes. Global/project mutations and their native-writer distinctions are documented in `../omp-settings/README.md`. Native handled-command receipts are distinct from persisted user messages; `accepted:null` never consumes a draft.

## Native todos

`session-todos.ts` owns one loaded session's native todo list. `read()` inspects only the current branch through the patched native `findLatestTodoStateEntry`: the newest `user_todo_edit` or successful `todo` tool result is authoritative, an empty state never falls back to live memory, and a malformed or oversized latest entry refuses inspection rather than showing older state. Reads never append. The ticket revision hashes the branch leaf, latest Todo entry and phases; the epoch binds the loaded owner. `mutate()` checks owner/busy/epoch/revision, reserves admission synchronously, runs native grammar, and calls the shared native `commitUserTodoEdit` followed by `ensureOnDisk`/`flush`. User changes persist both the native entry and user-attributed developer reminder.

Import reads a bounded file descriptor and rechecks the ticket after I/O. Export uses native path resolution; an uncertain write or post-commit failure latches `reconciliationRequired` and reports `OUTCOME_UNKNOWN`, never a replayable refusal. Completed receipts do not retain the owner's transient busy flag. Native extension/custom precedence uses the literal space-delimited token before builtin parsing, including native colon invocation syntax. Structured Markdown edits remain available when an extension owns `/todo`.

The desktop mounts a Todos section in the Environment card and handles show/edit/expand/collapse/copy as structured actions. Copy preserves native Markdown exactly. Import/export explicitly name the owning host's filesystem; the Markdown editor is not a claim that a TUI or configured external editor ran. Configured external editing now uses the original native Todo ticket and command/environment from its worker, with the existing editor helper and dock terminal. Durable job records, original cancellation and copy-only output recovery remain separate from native Todo truth; see `docs/native-todos-external-editor.md`. The existing host command journal and an owner-bound read endpoint retain rejected, pending and unknown receipts without storing a second Todo database. `fixtures/session-todos-native.ts` is the provider-free native proof; installed GUI focus/input acceptance remains separate.
