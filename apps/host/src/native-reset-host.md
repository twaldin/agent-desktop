# Shared native reset authority

The host creates one `ResetAccountAdmissions` for its `HostStore`. Manual saved-reset commands and the native automatic reset policy receive that exact instance, so one durable account claim prevents the other path from spending concurrently.

Worker reset owners are created only after the store, admissions authority, and policy exist. `WorkerRuntime` owns each returned owner and drains it with the corresponding native worker. Host shutdown calls `NativeResetPolicy.beginDispose()` before retiring workers, then waits for worker ownership and the shared policy journal before closing the store. Graceful reconnect preservation additionally depends on the worker runtime's retained-handoff lifecycle; a detached worker must transfer or drain reset ownership before the host closes storage.

The normal host stop preserves reconnect-capable workers. Configuration writes drain before worker retirement starts; worker handoff then runs alongside the remaining discovery-dependent cleanup. A refused handoff keeps the original store, lease, locator and worker ownership alive, and a later explicit `stop()` retries only the retained handoff while reusing the already-started cleanup drains. The store closes after worker handoff and the policy journal both drain successfully, even when an unrelated cleanup reports an error. Startup rollback is terminal: it attempts policy drainage after worker disposal even when disposal reports an error, keeps the store open through both attempts, and retains the original startup failure as the primary cause.
