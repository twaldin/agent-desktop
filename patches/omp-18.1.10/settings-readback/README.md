# Side-effect-free Settings persisted readback

The selected `@oh-my-pi/pi-coding-agent` 18.1.10 patch adds `Settings.capturePersistedReadback(paths)`. The capture retains the live instance's exact cwd, agent directory, explicit config overlays, and runtime overrides, while exposing only the requested setting paths. `read()` constructs a detached read-only parser, performs no flush, retry, storage open, migration, marker write, quarantine, or settings hook, and rejects a scope change through `set`, `override`, `clearOverride`, or `reloadForCwd` during the proof. Model-role-specific mutators do not advance this guard; their runtime values remain the captured snapshot, so the reader does not prove that every override stayed unchanged.

The snapshot states whether the source instance is writable, so a successful no-op `flush()` on `loadReadOnly` or in-memory settings cannot establish persistence. `projectDiscoveryStatus` is `incomplete` when native capability warnings report a failed provider or invalid item. `warning-free` only means no warning was surfaced; it is deliberately not a completeness claim because some existing providers log and silently drop malformed input. Callers that require proof of every possible higher layer need separate provenance. Explicit overlays remain strict read failures. The reader clears native filesystem discovery caches before reading and never substitutes the process's current `PI_CONFIG_FILES` for the captured overlay list.

This API reads selected settings only. It does not set, save, retry, authenticate, consume credits, invoke providers, or grant reset-policy authority.
