# Exact-session reset-policy lifecycle

The selected coding-agent package exposes one identity-bound lifecycle registrar in each factory binding. `beginClose` runs synchronously when that exact `AgentSession` begins terminal disposal, after native admission is fenced; it lets the owner cancel a held decision or other owner barrier that the drain itself may await. `drained` runs once only after the session's unbounded reset drain has joined prestarted usage fetches, owned pass bodies, post-reset refreshes, owner completion, and the attempted final `finished` checkpoint.

The signal belongs to the concrete session object rather than a native or registry session ID. Parking and cold revival therefore close the old session lifecycle and give the revived session a new binding. Setup failure after factory invocation uses the same `AgentSession.dispose()` path. Each registration captures its original callbacks and has its own phase flags, so duplicate listener objects unsubscribe independently, removal prevents a not-yet-invoked copied-snapshot callback, and reentrant or late registration receives each already-reached phase exactly once.

Listener exceptions are retained through terminal lifecycle settlement, do not skip independent listeners, and are reported through the existing native disposal logging path. A late replay exception after settlement is reported immediately. Native disposal keeps its existing bounded, log-and-complete convention while the lifecycle's native reset drain is unbounded; this primitive does not make host cleanup failures reject session disposal. A production host lifecycle callback must retain its own failure in host accounting rather than throw and assume native disposal propagates it.

This is an SDK prerequisite. It does not retire a host owner, change the 128-owner bound, close a shared reset channel, invoke worker-loss semantics, or enable reset policy. A host must separately keep root ownership and shared transport alive while retiring only the drained child's local resources.
