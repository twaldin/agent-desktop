# Owner-bound native browser controls

This candidate extends the selected OMP 18.1.10 browser metadata and viewport seam with exact-owner human actions. Every action requires the current native tab name, target ID, and a context captured from the actual page. The context includes the main-frame CDP loader ID plus the CSS viewport and scroll position. Navigation actions may tolerate changed scroll, while pointer, wheel, text, and key actions require the complete context to match.

Native browser runs and human actions exclude each other synchronously. A human action already reserved against a tab waits for an in-flight viewer capture to settle, then revalidates the exact tab and document before dispatch; later captures reject while that action is pending. A timed-out human action retains its busy slot until the underlying Puppeteer operation settles, preventing an uncertain click or text action from being repeated. Text uses Puppeteer's single `keyboard.sendCharacter` operation. Definite validation, owner, target, context, and busy failures use `BrowserActionRejected`; errors after input or navigation dispatch remain outcome-unknown to the host. The seam does not create agent tool calls, permission events, or transcript entries.

A pointer action can begin a main-frame navigation after Puppeteer confirms input dispatch. During that loader handoff, Chromium can briefly reject the read-only `Page.getNavigationHistory` call with `Not attached to an active page` even though the destination has loaded. Post-dispatch observation retries only this bounded set of transient CDP/context attachment errors for up to two seconds, revalidating the same live owner, tab, page, and target before every retry and after success. It never repeats the action. Closed, replaced, or stale targets and other post-dispatch failures remain outcome-unknown.

Run `bun patches/omp-18.1.10/browser-control/run-isolated.ts`. It copies the pinned package, applies the selected patch with zero fuzz, opens a disposable OMP-owned tab on a loopback site, and proves real click, click-triggered main-frame navigation, wheel, text, key, explicit navigation, CDP history including same-document entries, explicit viewport resize, reload, stale-context, mutual-exclusion, timeout, and modifier-cleanup behavior. Resize preserves the Puppeteer viewport's existing scale, mobile, touch, and orientation options; a tab without an existing Puppeteer viewport rejects resize before dispatch. The initial size remains the viewport selected by OMP browser configuration or the caller; viewer fitting requires an explicit resize action. It uses no provider, installed service, existing profile, or user page. Resize remains an explicit user action and is not automatic viewport fitting or streaming.
