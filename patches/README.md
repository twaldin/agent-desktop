# Maintained dependency patches

The package manifest and frozen Bun lockfile identify the patches used by a clean installation. Private source capsules and historical review packets are not installation inputs.

The OMP 18.1.10 patch was normalized for the first public release. Its 104 historical sections applied sequentially to the exact published archive; the resulting 55 changed files have identical contents and final modes in the current installer patch. The original cumulative patch remains in Git commit `b583fcb` and private immutable evidence.

Bun 1.3.14 has a [directory-mode bug when patches create nested files](https://github.com/oven-sh/bun/pull/33573). The installer encoding creates every new nested file with mode `100755`, followed by an explicit mode-only change to its intended `100644`. This lets Bun create searchable parent directories; the installed files end with their original intended permissions. Apply this paired encoding to later nested-file additions too. Do not remove those final mode changes or make the source files permanently executable.

A clean frozen Bun installation and a full byte/mode comparison against the intended package verified this encoding. When changing native code, regenerate the complete net patch against the pinned published archive and verify clean installation and final file modes. Do not append an unchecked sequence of overlapping patches. Preserve historical review freezes and distinguish installer encoding from behavioral source changes.

The Pierre `@pierre/diffs` 1.3.5 patch binds queued editor focus callbacks to their selection generation. Programmatic selections also reuse Pierre's selection-sync guard until real content pointer or keyboard input releases it: a delayed native caret event must not replace the managed range after the focus frames finish. The patch changes only the published editor JavaScript; package declarations, source maps and the version remain unchanged. The actual App acceptance exercises a freshly mounted target, repeated Back/Forward, restored hidden editors, and subsequent native pointer and keyboard selection.

The pi-catalog 18.1.10 patch adds the native Google Models `topK` observation to both the runtime model type and its public declaration. The coding-agent patch consumes it through the existing selected-model metadata hook. A dedicated native `google:top-k-v1` cache namespace keeps these Google observations separate from shared-catalog additive merging; the main catalog and other providers' cache policy remain unchanged. This enables accurate capability reporting, not a claim that every provider accepts every native Top K preset.

The coding-agent patch also extracts one native user-todo commit, `commitUserTodoEdit` in `src/tools/todo.ts`: live session state, the persisted `user_todo_edit` entry, and the user-attributed developer reminder the TUI `/todo` controller previously built privately. The TUI controller and the headless `/todo` dispatcher both call it, so non-TUI `/todo` edits now leave the same reminder as interactive ones. The headless verbs are exposed as `planTodoMutation`/`planTodoExport`/`planTodoImport` so a host can run the native grammar, re-guard, and commit itself; `findLatestTodoStateEntry` returns the branch entry `getLatestTodoPhasesFromEntries` reads. Matching declarations are patched under `dist/types`. The regenerated net patch preserves every earlier section and the paired nested-file mode encoding unchanged.
